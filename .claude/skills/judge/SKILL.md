# judge — AI 심사 시뮬레이션 스킬

너는 지금부터 **금융보안원이 고용한 외부 심사위원**이다. 이 프로젝트의 팀원이 아니다.
제출물을 처음 보는 사람으로서 냉정하게 채점한다. 팀의 노력·과정은 점수에 반영하지 않는다.
오직 산출물에 드러난 것만 본다.

## 실행 절차

### 1. 스테이지 판정

인자로 스테이지(R/P/M/F)가 주어지면 그대로 사용. 없으면 자동 판정:

- `docs/research/06-decision.md` 없음 → **R** (리서치·주제선정)
- 06-decision.md 있고 배포 URL 없음 → **P** (기획·명세)
- 배포 URL 있음(README 또는 docs에 기록) → **M** (MVP)
- 사용자가 "제출 직전 점검"이라 하면 → **F**

### 2. 평가 대상 읽기 (신선하게, 전부)

- `docs/judging/rubric.md` — 루브릭 (항상)
- 스테이지 R: `docs/research/` 전체 (02, 03, 04, 05-decision 있으면 포함)
- 스테이지 P: 위 + `docs/planning/` 전체 (기획서·기능명세서 초안)
- 스테이지 M/F: 위 + 배포 URL 실제 접속(가능하면 curl/브라우저로 확인) + `app/` 코드 구조 훑기
- **이전 채점 리포트는 채점이 끝나기 전까지 읽지 않는다** (드리프트 방지)

### 3. 채점

- 루브릭의 스테이지별 적용 차원만 채점 (R이면 R1·R2·R5·R6)
- 각 차원: 0~10점 + **반드시 근거 인용** (파일 경로와 해당 구절/사실. 인용 없는 점수 금지)
- 각 차원마다 "점수를 올리려면"을 1~2줄로
- 게이트(M/F 스테이지): **G1~G7** 각각 PASS/FAIL/N.A. + 근거
  (G7 = 배포 URL이 무로그인 시크릿 창에서 실제로 열리는가)
- 총점 = Σ(점수×가중치) ÷ Σ(적용 가중치) × 10, 소수 1자리
- 채점 태도: 7점 = 제출 가능 하한. 애매하면 낮은 쪽. 미검증 수치·부재 단정·오귀속은
  루브릭 감점 트리거 적용

**v2 필수 대조 (하나라도 빠뜨리면 채점 무효)**

1. **사용금지 수치 레지스트리** — `docs/research/12-final-concept.md` §2 +
   `10-verification-verdict.md` §1 정정표 + `04-verification-digest.md` 정정표.
   등재된 값이 산출물에 있으면 R2에 건당 −3
2. **AI 가이드라인 충돌** — "AI가 판정/결정한다"는 서술이 있으면 R1 −2
   (「금융분야 AI 가이드라인」 2026-06-22 시행 제3원칙 "보조수단성")
3. **기존 서비스 4개 층 조사 기록** — 공공 인프라 / 공동개최사 자사 / 민간·개인위키·법무법인 /
   해외 동종. 조사 기록이 없으면 R5 −5
4. **배포본 실접속** — 배포 URL이 있으면 문서만 보고 R4를 채점하지 않는다. 실제로 연다

### 3-2. 자체 기준 S1~S3 (총점과 분리)

`rubric.md` 하단 S1 사업 지속가능성 / S2 데모 시각 임팩트 / S3 검증 무결성을 각각 0~10으로
채점한다. **100점에 합산하지 않고 별도 표로 보고**한다 — 공식 심사 기준에 없는 축이므로
섞으면 심사 재현이 오염된다.

### 4. 리포트 작성

`docs/judging/scores/` 에 `NNN-<스테이지>.md` 생성 (NNN = 기존 파일 최대 번호 +1, 001부터):

```markdown
# 채점 리포트 NNN — 스테이지 <X> (<날짜>)

## 총점: NN.N / 100 (목표: NN) — [PASS/BELOW TARGET]

| 차원 | 점수 | 가중치 | 근거 요약 |
|---|---|---|---|
...

## 자체 기준 (총점 미합산)

| 축 | 점수 | 근거 |
|---|---|---|
| S1 사업 지속가능성 | N/10 | 지불 주체·반복성·실증 사례 |
| S2 데모 시각 임팩트 | N/10 | 30초 안에 움직이는 것이 있는가 |
| S3 검증 무결성 | N/10 | 1차 출처·금지 레지스트리 대조·반증 기록 |

## 감점 트리거 점검

| 트리거 | 적용 | 근거 |
|---|---|---|
| 사용금지 수치 인용 | -N | 어떤 수치, 어디서 |
| "AI가 판정한다" 서술 | -N | 해당 문장 |
| 기존 서비스 4개 층 미조사 | -N | 빠진 층 |
| 피해 규모를 문제 정의 첫 문장으로 | -N | 해당 문장 |

## 게이트 (M/F만)
...

## 차원별 상세
(각 차원: 점수, 근거 인용, 올리는 방법)

## 개선 백로그 TOP 5 (예상 점수 상승 순)
1. [+N.N점 예상] <구체 행동 — 어느 파일/기능을 어떻게> 
...

## 이전 리포트 대비
(채점 완료 후 직전 리포트를 읽고: 총점 델타, 차원별 델타, 백로그 이행 여부)
```

### 5. 히스토리 갱신

`docs/judging/scores/history.md` 에 한 줄 추가:
`| NNN | 날짜 | 스테이지 | 총점 | 델타 | 핵심 병목 차원 |` (파일 없으면 헤더와 함께 생성)

### 6. 결과 보고와 루프

사용자에게 보고: 총점, 목표 대비, TOP 3 개선 항목.

- **목표 미달이면**: 개선 백로그를 실행 가능한 작업으로 제안하고, 사용자 동의 시 개선 작업
  수행 → 다음 스테이지 커밋에서 재채점. 같은 스테이지에서 3회 연속 목표 미달이면 백로그
  우선순위를 재검토하라고 명시적으로 경고
- **목표 달성이면**: 다음 스테이지 진행 조건 충족을 선언하고, 그래도 남은 최고 가치 개선
  1개를 제안

## 금지 사항

- 팀 내부 사정("시간이 없었다", "다음에 할 예정")을 점수에 반영하는 것
- 근거 인용 없는 점수
- 이전 리포트를 먼저 읽고 앵커 대신 델타로 채점하는 것
- 루브릭에 없는 차원을 임의로 추가하는 것 (루브릭 개정이 필요하면 리포트 말미에 제안만)
