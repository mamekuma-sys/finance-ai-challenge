  “긴급하거나 부득이한 사유로 전화 또는 구술로 피해구제를 신청한 경우, 신청한 날부터

- **어디에:** `app/src/components/action-card.tsx:45-50,77-90`;
  계약 행동은 `app/src/lib/decision/rules.ts:175-189`.
- **왜 문제인가:** `docs/planning/11-spec-draft.md:428`은 “신청서를 해당 금융회사에

  승격해 사용자가 전화만 하면 서면 제출 단계도 진행한 것으로 오해하게 만든다.
- **구체적 수정 지시:** 이 카드의 1차 버튼을 “피해구제신청서 제출 방법 확인”으로 바꾸고
  `SRC-EASYLAW-STOPPAY`의 공식 신청 안내를 열어라. 같은 카드 안의 1394는
  “1394에 절차 상담하기” 2차 버튼으로 내려라. `PHONE_KEYS`에서
  `procedure:written_followup`을 제거하고, 1394 다이얼러 열기를 신청서 제출 카드의 현재
  상태로 환원하지 마라. 사용자가 실제 제출을 확인한 경우에만 기존
  `user_reported_requested`를 행동별 문구 “피해구제신청서를 금융회사에 제출했다고
  확인했어요”로 기록하도록 UI 라벨을 분기하라.

### B3. 화면의 공식 출처가 행동 문구의 핵심 동사를 충분히 지지하지 않는다

- **무엇이:** R1·R2·R4·R5·R7 카드가 하나의 부분지지 출처로 안전 기기 확보, 인증수단

- **어디에:** `app/src/lib/decision/rules.ts:78-145,199-267,319-349`;
  판정표 `app/docs/evidence-verified.md:234-240`.
- **왜 문제인가:** `docs/planning/11-spec-draft.md:694-707`은 출처 존재 확인을 넘어
  문장 지지 여부의 사람 검수를 요구한다. 전문가가 링크를 열면 근거가 없는 핵심 동사를
  즉시 발견할 수 있어 J3와 G4 신뢰를 동시에 무너뜨린다.
- **구체적 수정 지시:** `evidence-verified.md:234-240`이 제시한 대체 공식 출처를
  레지스트리에 추가하라. 최소한 R1의 다른 휴대전화·PC 사용 근거, R2·R4의 KISA 인증수단

  규칙별 `핵심 동사 → source_id → 원문 지지 문장` 표를 테스트 픽스처로 만들고 사람 검수
  PASS 없이는 노출하지 마라.

### B4. 시행일 미확인 템플릿을 비활성화하라는 계약이 코드 게이트에서 무시된다
