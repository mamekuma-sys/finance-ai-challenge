# 골든타임 정적 시각 목업

빌드·패키지 설치·외부 폰트 없이 브라우저에서 바로 여는 자체 완결 HTML 3종이다. 모든
스타일과 동작은 각 파일 안에 있으며, 공식 출처 링크를 사용자가 직접 누르기 전에는 외부
요청이 발생하지 않는다.

세 파일 모두 상단에 `구조화 상태 선택 데모 · 무로그인 · 서버 무저장`, 하단에 F-21의 `오분류
가능성 · 공식 채널 재확인 · 실제 처리 권한 부재`를 표시한다.

## r5/r6 정정 반영

2026-07-25 개정 계약 r5 H1과 r6 I1·I3에 맞춰 다음 위치를 함께 정정했다.

| 변경 위치 | 반영 내용 |
|---|---|
| 세 HTML의 전역 필수 후속 카드 | 긴급·부득이한 전화·구술 피해구제 신청에만 적용하고, 신청한 날부터 3일 이내 해당 금융회사에 피해구제신청서를 제출하도록 표시 |
| 같은 카드의 출처·추적 정보 | 현행 시행령 제3조와 1394 공식 안내를 보강하고 `TPL-WRITTEN-FOLLOWUP-001@1.1`로 통일 |
| 세 HTML의 상단 신뢰 고지 | F-01 구현을 전제하지 않는 `구조화 상태 선택 데모`로 표시 |
| 비교 목업의 설명·배지 | 측정 근거 없는 데모 소요시간을 제거하고 상태 변화와 3일 이내 서면 제출 후속만 설명 |
| `../w1a-report.md` | r5/r6 정정 사실, 현재 템플릿 버전, 독립 금지 문자열 검사 사용법 기록 |

서면 제출이 카드의 본 행동이며 1394는 피해상담·관계기관 연계를 위한 후속 상담으로
구분한다. 다른 템플릿 버전은 변경하지 않았다.

## 열어보는 법

Finder에서 HTML 파일을 더블클릭하거나 브라우저 주소창에 파일을 끌어 놓는다. 로컬 서버나
빌드는 필요 없다. 터미널에서 경로만 확인하려면 다음과 같이 사용할 수 있다.

```bash
ls app/docs/mockup/0*.html
```

상단 `라이트`와 `다크` 버튼으로 두 테마를 즉시 전환한다. 처음 열 때는
`prefers-color-scheme`을 따르며, 버튼을 누른 뒤에는 현재 문서에서 선택한 테마를 쓴다.
`03-desk-easy-mode.html`의 `다음 행동 보기`는 카드 1→2→3→4 순서로 전환하되 항상 하나의
카드만 보이게 한다.

## 대비비 검증

### 계산식

각 sRGB 채널을 0~1로 정규화한 뒤 다음 공식을 직접 계산했다.

```text
c <= 0.04045: c_lin = c / 12.92
c > 0.04045:  c_lin = ((c + 0.055) / 1.055) ^ 2.4
L = 0.2126 R_lin + 0.7152 G_lin + 0.0722 B_lin
contrast = (L_lighter + 0.05) / (L_darker + 0.05)
```

판정선은 본문 4.5:1, 큰 텍스트와 UI 경계 3:1이다. 아래는 HTML에서 실제 사용한 정보성
색쌍의 계산 결과다. 배경과 표면의 비정보성 명도 차는 판정 대상이 아니며, 모든 카드·필드에는
별도의 3:1 이상 경계를 둔다. 반올림 전 원값으로 판정하고 표에는 소수 둘째 자리까지 적었다.

## 360px·768px·1440px 레이아웃 확인

브라우저 개발자 도구의 반응형 모드에서 각 파일을 아래 순서로 확인한다.

1. viewport 너비를 360, 768, 1440px로 각각 설정한다.
2. 라이트와 다크를 각각 선택한다.
3. 페이지 처음부터 하단 F-21 고지까지 스크롤한다.
4. 개발자 도구 Console에서 다음 식이 `true`인지 확인한다.

```js
document.documentElement.scrollWidth === window.innerWidth
```

5. Tab만 사용해 건너뛰기 링크, 테마 버튼, 공식 출처 링크, `왜 이 순서인가`, 복사 또는
   다음 행동 버튼을 이동한다. 모든 포커스에 3px 이상 링이 보여야 한다.

예상 레이아웃:

| 너비 | 01 기본 | 02 비교 | 03 고령자 |
|---:|---|---|---|
| 360px | 행동 카드와 보조면 1열, 상태 칩 1열 | 이전 상태 다음 변경 상태의 1열 적층 | 한 카드, 상태 칩 1열, 58px 전체폭 버튼 |
| 768px | 행동 레일 1열, 금지 행동 아래 2개 보조 카드 | 비교 패널 1열 적층 | 한 카드, 최대 920px 안에서 유동 |
| 1440px | 1100px 중앙 정렬, 행동 1열 + 보조면 | 1100px 중앙 정렬, 이전/변경 2열 | 920px 중앙 정렬, 한 카드 |

긴 URL·템플릿 ID는 `overflow-wrap:anywhere`, grid 자식은 `min-width:0`, 모든 요소는
`box-sizing:border-box`를 사용한다. 각 모바일 미디어 쿼리는 페이지 전체의 가로 스크롤을
필요로 하는 표나 고정폭 요소를 만들지 않는다.

## React/Next 구현팀 이관 주의점

- 목업의 카드 문장을 복사해 별도 상수로 재해석하지 말고 §4.5 결정 엔진 결과의
  `merge_key`, `purpose_slots`, `official_sources`, `template_version`을 그대로 렌더한다.
- `transfer_state=already_sent`의 `TPL-WRITTEN-FOLLOWUP-001`은 항상 노출 4개 안의 단일
  `필수 카드`여야 한다.
- 사용자의 사건 상태와 행동 이벤트 이력은 `sessionStorage` 전용이다. 개인 부속면 4종
  필드는 브라우저 메모리 밖으로 보내지 않는다.
- 테마 초기값은 CSS `prefers-color-scheme`으로 먼저 그려 테마 전환 전 깜빡임을 피한다.
  수동 테마는 `data-theme` 한 곳에서만 제어한다.
- 고령자 모드는 글자 확대만 하지 말고 한 번에 가시 카드 하나, 본문 20px 이상, 핵심 버튼
  48px 이상을 함께 유지한다. 카드 전환은 `aria-live=polite`로 알린다.
- `details/summary`, `button`, `a`, `fieldset/legend` 같은 네이티브 요소를 유지한다. 클릭
  가능한 `div`로 바꾸지 않는다.
- 색 토큰과 함께 `지금 먼저`, `필수 카드`, `추가`, `제거`, `순위 변경`, `자동 관측`,
  `사용자 진술` 텍스트를 보존한다.
- 외부 공식 링크는 허용 목록과 검수 단계를 통과한 URL만 사용한다. CDN, 웹폰트, 원격 이미지
  의존성을 추가하지 않는다.
- 전환은 150~250ms 안에서 끝내고 `prefers-reduced-motion`을 존중한다. 가짜 로딩,
  인위적 지연, 가짜 단계 이벤트를 만들지 않는다.
- 실제 앱 E2E에서 360·768·1440px의 `scrollWidth === innerWidth`, 키보드 포커스,
  라이트·다크 대비, 네트워크 요청을 다시 자동 계측한다.
