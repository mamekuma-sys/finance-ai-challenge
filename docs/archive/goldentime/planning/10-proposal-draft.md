## 1. 서비스 명칭

### 골든타임(GoldenTime) — AI 사기대응 상황실

- **한 줄 정의:** 송금·앱 설치·인증정보 노출 직후의 금융소비자에게 AI 판정보다 먼저 공식
  첫 행동을 제시하고, 한 번 입력한 사건 맥락을 기관 전달용 브리핑과 사용자 확인 상태로
  이어 주는 무설치 웹 서비스
- **서비스 약속:** “이거 사기인가?”를 **지금 할 행동 → 공개 수법 패턴과의 유사 신호 →
  다음 기관에 전달할 준비**로 바꾼다.
- **권한 경계:** 판단·행동 준비를 돕되 지급정지, 신고 접수, 수사·법적 판정은 금융회사와
  경찰 등 권한 있는 기관이 수행한다.

## 2. 아이디어 기획 핵심내용(요약)

> **“방금 송금한 이용자가 30초 안에 첫 전화 대상, 말할 문장, 긴급하거나 부득이한 사유로
> 전화·구술 피해구제를 신청한 날부터 3일 이내 할 일을 얻습니다.”** — 이 문장은 **데모
> 목표**이며 제품 보증이 아니다. 다만 긴급 안전 카드
> 렌더링의 배포 환경 상한(`Rule 0`, p95 ≤ 2초 — 모델 호출 없음)이 이를 구조적으로
> 뒷받침한다.

- **첫 화면:** “돈을 보냈거나, 앱을 설치했거나, 인증정보를 알려주셨나요?”를 최상단에 묻고,
  해당하면 AI 결과를 기다리지 않는 결정적 안전 카드를 즉시 표시
- **와우 장면(복합 상태 변화):** 같은 합성 메시지의 `송금 전`과 `송금 직후`를 나란히 놓고
  (p95 ≤ 5초 재구성), `악성 앱 설치`를 추가로 선택하면 금지 행동 등장, 안전 기기 전제 삽입,
  행동 카드 재구성, 3일 이내 서면 제출 후속 유지, 부속면 필드 변화가 한 화면에서 일어나는
  모습을 시연
- **입력 원칙:** 검수된 합성 샘플 3건이 기본이며, 실제 메시지는 기기 내 자동 가림 미리보기와
  사용자 확인을 거친 뒤 선택적으로 전송
- **핵심 산출물:** 조치 결정 엔진 기반 행동 카드, 행동 이벤트 이력, 고정 대응 문구,
  신고 준비 브리핑 이중 구성 — 참고용·미제출 표시가 있는 서버 생성 비식별 PDF + 브라우저
  에서만 생성되는 개인 부속면
- **처리 구조:** LLM 3단계, 결정적 규칙 2단계, 템플릿 조립 1단계로 구성된
  **6단계 처리·검증 파이프라인**
- **상황실:** 개인 사건은 자기 브라우저 안에서만 파이프라인 타임라인으로 보고, 공개
  `/room`은 합성 시드 사건만 명시적으로 표시
- **신뢰 장치:** 독립 홀드아웃·적대 입력 평가, 허용 출처 ID 대조, 고정 템플릿 경계 검사,
  실패 사례 공개

## 3. 문제 정의 및 제안 배경

### 3.1 좁힌 문제 정의

보이스피싱 대응 수단과 기관 연계는 이미 존재한다. 2023년 개소한 통합신고대응센터도 112
신고를 사건 접수·악성 앱 차단·지급정지와 연계한다. 그러나 **소비자 화면에서 상태별 순서,

않는다.** 골든타임은 이 소비자 경험의 공백을 다룬다.

## 4. 서비스 컨셉 및 차별성

### 4.1 AI보다 먼저 작동하는 긴급 우회로

첫 화면에서 긴급 질문에 하나라도 해당하면 금융회사 대표번호·112 우선 행동을 즉시 제시한다.
AI 분석은 병렬로 진행하고 결과는 행동 카드 아래의 보조 근거로 붙인다. 핵심 상태 스키마는
기획서와 기능명세서에서 다음 값으로 통일한다.

| 필드 | 허용값 |
|---|---|
| `transfer_state` | `not_sent / already_sent / unknown` |
| `device_compromise_state` | `none / suspected_app / remote_control / unknown` |
| `credential_exposure_state` | `none / suspected / shared / unknown` |
| `personal_data_exposure_state` | `none / suspected / shared / unknown` |
| `user_role` | `self / family_proxy` |
| `safe_device_available` | `yes / no / unknown` |

복수 위험이 있으면 일치하는 **모든** 규칙을 수집해 위해 순위로 정렬·병합하는 조치 결정
엔진(기능명세서 §4.5의 총함수)이 최대 4개의 행동 카드를 만든다. 송금 완료 상태에서는
어떤 병합 결과에서도 3일 이내 서면 제출 후속 절차가 전역 규칙으로 보존된다. 악성 앱·원격제어가
의심되면 감염 의심 기기에서 금융 앱을 사용하거나 대표번호를 검색하도록 안내하지 않고,
안전한 별도 기기 확보 여부를 먼저 확인한다. 이미 송금했다면 해당 금융회사와 112를 우선하고,
본인계좌 일괄지급정지를 사기이용계좌 지급정지의 대체 수단처럼 표시하지 않는다.

### 4.2 행동 카드와 행동 이벤트 이력

행동 순서와 공식 문구는 AI가 만들지 않고 상태 조합, 금지 행동, 공식 출처, 템플릿 버전이
결합된 조치 결정 엔진으로 정한다. 브라우저가 외부 기관의 실제 처리 결과를 알 수 없으므로
단일 성공 상태를 두지 않는다. 이력은 단일 현재값 덮어쓰기가 아니라 `{이벤트 ID, 행동 ID,
이벤트 유형(기록/정정), 발생 시각, 상태, 출처, 이전 상태}`를 가진 **이벤트 배열
(append-only)**로 기록하며 정정 이벤트가 대상 이벤트를 지목한다. 이 이력은 감사 원장이
아니라 **사용자 기기의 로컬 행동 이력**이며 화면에 “내 기기 보관”으로 표기한다.

| 사실 상태 | 의미 | 기록 출처 |
|---|---|---|
| `viewed` | 행동 카드를 봄 | `ui_event` |
| `dialer_opened` | 전화 앱 열기를 선택함 | `ui_event` |
| `user_reported_connected` | 사용자가 통화 연결 사실을 확인함 | `user_statement` |
| `user_reported_requested` | 사용자가 요청 전달 사실을 확인함 | `user_statement` |
| `user_reported_receipt_confirmed` | 사용자가 기관 접수 사실을 진술함 | `user_statement` |
| `not_applicable` | 사용자가 현재 사건에 해당하지 않는다고 확인함 | `user_statement` |
| `unknown` | 아직 알 수 없거나 사용자가 모른다고 답함 | `ui_event` 또는 `user_statement` |

자동 측정은 `official_action_presented`와 `dialer_opened`까지만 사용한다. 통화 연결·요청
전달·접수는 사용자 확인값 또는 사용성 테스트 관찰로만 다룬다. 이 이력은 사용자 사건과 함께
`sessionStorage`에만 유지한다.

### 4.3 6단계 처리·검증 파이프라인

| 순서 | 단계 | 실행 유형 | 역할 |
|---:|---|---|---|
| 1 | 트리아지 | LLM | 마스킹된 입력에서 확인된 사실과 누락 슬롯 추출 |
| 2 | 사건 분석 | LLM | 검색된 공개 패턴 안에서 위험·반대 신호와 근거 충분도 작성 |
| 3 | 피해자 케어 | LLM | 쉬운 설명과 최대 3개의 확인 질문 제안 |
| 4 | 조치 결정 | 결정적 규칙 | 상태 조합에 맞는 1·2·3순위와 금지 행동 선택 |
| 5 | 브리핑 조립 | 고정 템플릿 | 승인된 문구와 검증된 슬롯으로 행동 카드·PDF 조립 |
| 6 | QA | 결정적 규칙 | 스키마, 출처 ID, 상태 모순, 템플릿 경계, 개인정보 검사 |

판정의 `evidence_strength`는 **근거 충분도**이며 통계적으로 보정된 확률이 아니다.
`source_refs`는 그 요청에서 검색된 허용 ID 집합과 결정적으로 대조한다. 근거 라벨은 개별
사건의 사기 확정이 아니라 **“공개 수법 패턴과의 유사 신호”**로 표시한다.

### 4.4 경쟁·인접 서비스 비교

## 5. 활용 데이터 및 생성형 AI 모델 적용 방안

### 5.1 데이터 원칙

- **프로젝트 데이터셋:** 실제 피해자·금융데이터·개인정보 0건. 공식 자료에서 사람이 최소
  사실 필드만 추출하고 합성 사례로 다시 작성한다.
- **사용자 자유 입력:** 합성 샘플이 기본이다. 선택 입력은 기기 내 1차 가림 미리보기와 사용자
  확인, 서버 2차 마스킹을 거쳐 일시 처리하며 서버 DB·로그·공개 화면에 저장하지 않는다.
- **저장 분리:** 서버 DB·공개 상황실·집계는 합성 사건 전용이다. 사용자 사건의 상태·판정·
  행동 이벤트 이력은 자기 브라우저의 `sessionStorage`에만 둔다.
- **출처와 라이선스:** 소스마다 라이선스, 사실 추출 허용 판단, 상업 이용 가능 여부, 원문
  모델 입력 여부, 보존 범위, 추출자·검수자·파생 시나리오를 기록한다. 이용조건이 바뀌면
  연결된 파생 레코드를 연쇄 격리한다.

### 5.4 생성형 AI의 역할과 금지 경계

LLM은 비정형 사실 추출, 공개 패턴 비교 설명, 쉬운 말·확인 질문에만 사용한다. 긴급 행동
순서, 공식 기관·연락처, 지급정지·신고 절차, 신청한 날부터 3일 이내 서면 제출 후속 문구는
규칙과 버전 관리된
고정 템플릿이 결정한다. 템플릿마다 `official_source`, `source_effective_date`,
`source_reviewed_at`, `next_review_at`, `change_log`, `template_version`을 필수로 둔다.

M단계 인수 검수에는 다음이 포함된다.

- 이번 요청에서 검색된 허용 출처 ID와 `source_refs`의 정확 일치
- 출처가 실제 문장을 지지하는지에 대한 사람 표본 검수
- 보호 템플릿 경계 위반, 개인정보 누출, 금지 행동 노출의 결정적 검사
- 공식 출처·시행일·검수일·재검토 예정일·변경 이력이 비어 있으면 배포 차단

### 5.5 용도별 독립 평가셋

| 평가셋 | 규모 | 용도 | 공개 규칙 |
|---|---:|---|---|
| 데모 | 합성 3건 | 랜딩·2분 시연 | 평가 성능 산출에 사용하지 않음 |
| 개발·회귀 | 합성 40건 | 구현·프롬프트·규칙 회귀 | 안전성 성능 산출에 사용하지 않음 |
| 비공개 홀드아웃 | 합성 40건 | 수법별 일반화 평가 | 프롬프트 튜닝 노출 없음 명시 후 결과 공개 |
| 적대 입력 | 합성 20건 | 인젝션·형식 교란·경계 위반 평가 | 공격 범주와 실패 사례를 결과에 포함 |

네 집합은 시나리오 ID가 겹치지 않으며, 수법 6종과 정상·불확실 맥락을 포함한다. 안전성
리포트는 홀드아웃과 적대셋 결과만 사용해 분모, 클래스별 건수, 95% 구간, 실패 범주,
라벨링 절차를 공개한다. 측정 지표는 수법별 FN/FP/유보, unsafe action rate,
citation validity, PII leakage, template boundary violation, injection attack success rate,
fallback correctness다.

평가셋 계약은 **데모 3건 / 개발·회귀 40건 / 비공개 홀드아웃 40건 / 적대 입력 20건**이다.

안전성 지표 9종의 분자·분모·집계 규칙·구간 방법(Wilson 95% 병기)과 **사전 배포 차단
임계값**(PII 누출 0건, 템플릿 경계 위반 0건, 홀드아웃 위험군 FN ≤10%, 인젝션 성공 ≤5%,
citation validity ≥95%, fallback correctness 100%), 그리고 **제품 KPI 5종의 통과선**은
기능명세서 §5.4에 고정했고, 평가 실행 전에 버전 관리로 등록해 결과를 본 뒤 바꾸지 않는다.
차단 판정은 점추정치 기준이며 신뢰구간은 병기용이다. 홀드아웃 40건+적대 20건의 결과는
**“예비 평가”**로 명명하고 신뢰구간을 병기하며 일반화 성능 주장을 하지 않는다.

| 오행동률 | 조치 결정표의 금지 행동을 선택하거나 우선순위를 어긴 과업의 비율 | 상태 조합별 사용성 테스트 관찰과 결정표 대조 | AI 판정 정확도와 별도 측정 |
| 브리핑 필수 필드 충족률 | 생성된 브리핑이 승인 스키마의 필수 필드를 채운 비율 | JSON Schema·템플릿 버전 자동 검사 | 기관 접수 적합성이나 실제 제출 성공을 뜻하지 않음 |
| 상담 시뮬레이션 재질문 수 | 상담원이 핵심 사건 필드를 다시 묻는 횟수 | 동일 합성 사건의 **브리핑+부속면 포함·미포함** 조건 비교(합성 상담 시뮬레이션) | 실제 콜센터 효과는 기관 파일럿 전 주장하지 않음 |
| AI 기여 비교(KPI ⑤) | 규칙형 폼(고정 질문) 대비 LLM 보조(비정형 추출+맞춤 질문)의 개선 폭 | 동일 합성 사건 이중 조건 실험 — 사실 추출 누락률, 확인 질문 수, 브리핑 슬롯 정확도, 쉬운 설명 이해도(테스트 참가자 평가) | “왜 AI인가”의 실증 답변. LLM 우위가 확인되지 않은 항목은 결과를 그대로 공개 |

통화 연결·요청 전달·접수는 자동 KPI로 계산하지 않고 사용자 확인값 또는 관찰값으로 분리한다.
모든 성능 수치는 M단계 실측 전에는 제시하지 않으며, **KPI별 통과선 초기값은 평가 실행 전에
버전 관리로 등록한다**(기능명세서 §5.4.3 — 오행동률 금지 행동 0건·우선순위 위반 ≤10%,
재질문 수 중앙값 30% 이상 감소, AI 기여 누락률 상대 20% 이상 감소 등).

확장한다.
