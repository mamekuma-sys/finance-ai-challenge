# 개정 라운드 2 — 아키텍처 결정 (14-human-review-r2 반영)

작성: 2026-07-24. 패널 2라운드의 M0 계약 동결 4조건 + 잔여 TOP 5의 "문서 단계" 항목을
닫는 확정 결정 E1~E8. `10`·`11` 개정은 이 계약을 따른다.

## E1. 조치 결정 엔진 총함수화 (M0 조건 1)

- **조건식 정규화**: R1~R7의 조건을 전부 순수 열거형 조건식으로 재작성 — "R1·R2 비해당",
  "확정 불가", "금전·기기·인증정보 노출 없음" 같은 참조·자연어 조건 금지.
  `transfer_state != already_sent` 표기 금지 — `unknown`은 별도 분기(`not_sent`만 명시).
- **실행 알고리즘 명문화**: ① 일치하는 모든 행 수집 → ② `severity_rank` 정렬
  (`remote_control(1) > suspected_app(2) > already_sent(3) > credential shared(4) >
  credential suspected(5) > personal_data(6) > 기본(7)`; unknown 상태는 해당 축 확인
  질문을 최우선 삽입) → ③ `merge_key`(채널×목적) 단위 중복 제거, 높은 severity 행의
  행동 우선 → ④ **필수 후속 절차는 규칙과 독립인 전역 규칙으로 승격**:
  `transfer_state=already_sent → TPL-WRITTEN-FOLLOWUP-001 필수 포함` (어떤 병합 결과에서도
  탈락 불가) → ⑤ 금지 행동은 합집합 → ⑥ 우선순위 재번호(최대 4개 카드, 초과분은 "다음
  단계"로 접기).
- **복합 조합 인수 스냅샷 5종**을 명세에 표로 고정: (a) 송금 완료+악성 앱+안전 기기 없음
  (b) 송금 완료+원격제어+인증정보 공유 (c) 송금 여부 unknown+인증정보 공유 (d) 가족
  대리+송금 완료(본인 제한 절차 안내 포함) (e) 개인정보 공유만+타 상태 일부 unknown.
  각각 기대 카드 순서·금지 행동·필수 후속·템플릿 버전 명시.

## E3. 브리핑 이중 구성 — 개인 부속면 (M0 조건 3)

- **채택안: 브라우저 전용 개인 부속면(Private Annex)**. 거래 핵심 필드(금융회사명, 송금
  시각, 금액대, 수취 정보 메모)는 사용자가 **브라우저에서만** 입력, 클라이언트 사이드에서
  부속 페이지를 생성(서버 전송·저장·모델 입력 없음).
- 산출물 = ① 서버 생성 비식별 브리핑 PDF(현행) + ② 기기 내 생성 개인 부속면(브라우저
  인쇄·저장). 부속면 상단에 "이 면은 내 기기에서만 생성됨 — 서비스 서버로 전송되지 않음" 명시.
- **상담원 핸드오프 경계**: v1은 사용자 매개 — 사용자가 본인 기기에서 제시하거나 본인이
  전송한다. 서비스는 전송 채널·상관키를 제공하지 않는다(은행 파일럿에서 별도 계약·스키마).
- KPI 정합: "초기 정보 수집 시간·재질문 수" 측정은 **부속면 포함 조건**의 상담 시뮬레이션
  으로 정의(합성 데이터, 실고객 데이터 없음).

## E4. 판정 규칙·임계값·AI 기여 사전 고정 (M0 조건 4)

- **안전성 지표 7종 판정 규칙 표**: 각 지표의 분자/분모/한 출력 다중 위반 집계(사건 단위
  최대 1회 + 위반 유형별 부기)/구간 방법(Wilson 95%) 명시.
- **사전 배포 차단 임계값(초기값, 평가 전 버전 관리 등록)**: PII leakage **0건**, template
  boundary violation **0건**, 홀드아웃 위험군 FN(위험→낮음) **≤10%**, injection 성공
  **≤5%**, citation validity **≥95%**, fallback correctness **100%**. 미달 시 해당 기능
  비활성·배포 차단.
- **표본 한계 명시**: 40+20건 결과는 "예비 평가"로 명명, 신뢰구간 병기, 일반화 주장 금지.
  라벨링: 작성자 외 1인 이상 독립 라벨(1인 개발 한계상 라벨 규칙서+재검토로 대체 시 그 사실
  명시), 불일치는 규칙서 개정 후 재라벨.
- **AI 기여 비교 실험 신설(KPI 5호)**: 동일 합성 사건을 ① 규칙형 폼(고정 질문) ② LLM 보조
  (비정형 추출+맞춤 질문) 두 조건으로 처리 — 사실 추출 누락률, 확인 질문 수, 브리핑 슬롯
  정확도, 쉬운 설명 이해도(테스트 참가자 평가)를 비교. "왜 AI인가"의 실증 답변.
- **토큰 계약**: `POST /api/v1/tokens` — 목적 제한 고지 동의 → 단기 토큰(TTL 10분,
  scope `analyze:free_text`, 재발급 가능, 서버는 해시만 보관, 폐기 API). 헤더
  `Authorization: Bearer`. `AnalyzeRequest`: `text` 존재 시 `masking_confirmed=true`
  **조건부 필수**(JSON Schema `if/then`) — 아니면 `422`. **MCP 자유 텍스트도 동일 토큰
  필수** + 도구 description에 "호출 클라이언트가 기기 내 민감정보 제거 책임" 명시 + 서버
  2차 마스킹 동일 적용. UI는 가림 확인 시 토큰 자동 발급(무로그인 유지).

## E5. 행동 이벤트 원장 (잔여 TOP5-5)

- `ActionFactEvent[]`: `{event_id, action_id, occurred_at, state, source, previous_state}`
  배열로 교체(단일 fact_state 덮어쓰기 금지). 허용 전이 목록 명시
  (`viewed→dialer_opened→user_reported_connected→user_reported_requested→
  user_reported_receipt_confirmed`; `not_applicable`·`unknown`은 어느 상태에서든 기록 가능,
  정정 이벤트 허용).
- `receipt_confirmed` → **`user_reported_receipt_confirmed`** 개명 (증거 수준을 이름에).
- 저장은 여전히 `sessionStorage` 전용.

## E6. 30초 약속의 인수 기준 연결 (새 결함 4.6)

- 인수 기준 추가: "긴급 질문 응답 선택 → Rule 0 안전 카드 렌더링 **p95 ≤ 2초**(배포 환경,
  모델 호출 없음)", "상태 전환 비교 재구성 **p95 ≤ 5초**". 측정 시작·종료 이벤트 정의.
- 기획서의 "30초 안에"는 **데모 목표** 라벨 병기(제품 보증 아님) — 단 Rule 0 상한이 이를
  구조적으로 뒷받침함을 명시.

## E7. 데모 중심 재배치 (새 결함 4.7)

와우 장면 = 복합 상태 변화(악성 앱 추가 선택 시: 금지 행동 등장 + 안전 기기 전제 + 행동
카드 재구성 + 3영업일 후속 유지 + 부속면 필드 변화). 파이프라인 애니메이션·공개 피드는
보조. §3.3 데모 표를 이 기준으로 재작성.
