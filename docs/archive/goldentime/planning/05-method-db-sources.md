# 사기 수법 DB 공개 출처 확정안

- 조사·접속 확인일: 2026-07-24
- 확정 소스: 9개
- 적용 원칙: 공개 여부와 별개로, 실제 피해자의 금융정보·개인정보와 실제 전화번호·계좌번호는 수집하지 않는다. 원문 시나리오는 라이선스가 명확히 허용하는 경우에도 그대로 학습·노출하지 않고, 사실인 수법 패턴만 구조화한 뒤 합성 사례로 다시 쓴다.

## 0. 조사 범위와 판정 기준

아래 표에는 조사일에 상세 페이지 본문과 해당 페이지의 이용조건 문구를 직접 확인한 URL만 넣었다. 검색 결과에서 제목만 발견했거나 상세 페이지 접속·페이지별 라이선스 확인이 되지 않은 후보는 제외했다.

수법 DB의 기본 매핑 필드는 다음과 같이 둔다.

| 필드 | 의미 |
|---|---|
| `method_category` | 기관사칭, 지인사칭, 대출빙자, 배송사칭, 스미싱, 메신저피싱 등 |
| `channel` | 전화, SMS, 메신저, 이메일, 웹, 대면 |
| `impersonated_entity` | 사칭 주체의 범주. 실제 개인명은 저장하지 않음 |
| `lure` | 명의도용, 저금리 대환, 과태료, 배송, 지원금, 계정 이상 등 미끼 |
| `requested_action` | 송금, 현금전달, URL 클릭, 앱 설치, 인증번호 제공, 고립·숙박 등 |
| `pressure_tactic` | 긴급성, 비밀유지, 처벌 위협, 보상 약속, 권위 사칭 |
| `indicator_features` | 전화번호·URL·계좌번호의 **형태적 특징 또는 해시**. 원문 실번호·실계좌는 저장하지 않음 |
| `outcome_type` | 금전 편취, 개인정보 탈취, 계정 탈취, 악성 앱 설치 등 |
| `source_refs` | 소스 ID, 제목, URL, 게시일, 접속일, 이용조건, 변환 이력 |

### 소스 해석 시 주의사항

1. S4·S6·S7은 집계 통계이므로 특정 입력을 “사기”로 판정하는 직접 증거가 아니라, 분류체계와 위험 우선순위를 보정하는 보조 근거다.
2. S5의 URL은 공개 데이터여도 활성 악성 인프라일 수 있다. URL 전체 문자열의 검색·클릭·화면 노출을 금지하고 정확 일치 검사는 해시로만 수행한다.
3. S8은 데이터셋명이 “사기계좌 정보”이지만 확인된 컬럼에는 계좌번호가 없다. 대신 피해금액과 피해자 속성이 포함되므로 대회 규정의 실제 금융데이터 금지에 걸린다고 보수적으로 판정했다.
4. 모든 화면 인용에는 원 출처, 게시일, URL, 접속일, 이용조건을 함께 남긴다. “공공누리 1유형”은 출처표시가 필수다.

### 1위: S1 금융위·금감원 「보이스피싱 피해예방 10계명」

- 기관사칭, 지인사칭, 대출빙자, 악성 앱, 배송사기까지 MVP 핵심 수법을 한 문서에서 포괄한다.
- 접근→고립·압박→앱 설치·송금 요구로 이어지는 단계가 명확해 설명 가능한 판정 규칙을 만들기 좋다.
- 단, 원문 대화·번호·URL을 복제하지 않고 패턴 원자화 후 합성하는 것이 수집 완료 조건이다.

### 2위: S2 KISA 보호나라 스미싱·피싱 주의보

- 사회 이슈와 계절에 따라 바뀌는 최신 미끼를 가장 빠르게 반영할 수 있다.
- `미끼 → URL 클릭 → 피싱사이트/악성 앱 → 정보·금전 탈취` 흐름을 SMS 판정 규칙으로 변환하기 쉽다.
- 저작권 고지가 제한적이므로 원문 보관이 아니라 수법 팩트와 출처 메타데이터만 보관한다.

### 3위: S4 경찰청 보이스피싱 현황

- 개인정보 없이 전국 단위 기관사칭형·대출사기형의 장기 추세를 제공하고 이용허락범위도 명확하다.
- 시나리오 생성 비율, 위험도 기본값, 대시보드 설명 수치에 사용할 수 있다.
- 행이 10개뿐이고 세부 시나리오는 없으므로 S1·S2의 패턴을 보조하는 통계 소스로 사용한다.

S5의 대규모 피싱 URL은 정확 일치 탐지에 유용하지만, 악성 링크 취급·갱신·격리 저장이 필요한 운영 데이터이므로 MVP 1차 수집 후 별도 보안 작업으로 진행한다.

## 4. 합성 시나리오 생성 계획

### 4.1 원문에서 패턴만 추출

원문 문장이나 실제 사례를 생성 모델에 통째로 넣지 않는다. 사람이 먼저 다음의 비창작적 사실 단위로 정규화한다.

```yaml
method_category: institution_impersonation
channel: phone_then_sms
impersonated_entity: public_investigative_agency
lure: identity_misuse
requested_action:
  - maintain_secrecy
  - move_to_isolated_place
  - install_app
  - transfer_money
pressure_tactic:
  - arrest_threat
  - urgency
outcome_type:
  - credential_theft
  - financial_loss
source_refs:
  - S1
```

이 구조화 레코드에는 원문의 대사, 인명, 실번호, 계좌, 활성 URL, 피해자의 나이·성별·피해액을 넣지 않는다.

### 4.2 합성 재작성 원칙

1. **인물·기관**: 이름은 `김민준`, `이서연` 같은 흔한 실명도 피하고 `상담원 A`, `이용자 B`처럼 역할명만 쓴다. 기관은 `가상 수사기관`, `예시은행`처럼 허구임이 명확한 이름을 사용한다.
2. **전화번호·계좌번호**: 실제 형식과 혼동되지 않도록 `010-0000-0000`, `000-000000-00-000` 같은 명백한 더미를 사용한다. 판정 로직 테스트에는 별도 `is_synthetic=true`를 붙인다.
3. **URL**: 인터넷 표준상 예시용인 `.invalid` 또는 `example.com`만 사용한다. 예: `https://delivery-check.invalid/a7k2`.
4. **금액·시간·장소**: 원문의 값을 옮기지 않고 범주형 표현 또는 무작위 합성값을 쓴다. 원 사례와 조합이 재식별되지 않도록 피해자 속성은 생성하지 않는다.
5. **문장**: 원문 표현을 바꾸는 단순 치환이 아니라 접근 채널, 미끼, 압박, 요구행동, 결과를 새로 조합한다. 원문과 연속 구절이 겹치는지 자동 검사하고, 상투적 경고 문구를 제외한 유사 문장은 폐기한다.
6. **균형 데이터**: 수법별 사기 예시뿐 아니라 “공식 앱에서 사용자가 먼저 시작한 정상 거래”, “대표번호로 재확인한 안전 사례” 같은 합성 정상·불확실 예시를 함께 만든다.
7. **출처 추적**: 각 합성 시나리오에 `source_refs`, 생성 규칙 버전, 생성일, 검수자, 원문 비복제 확인값을 저장한다. 화면에는 출처명과 원문 링크를 표시하되 원문 전체를 재게시하지 않는다.

### 4.3 지표 처리 원칙

| 지표 | 원본 수집 | DB 저장 | 합성 시나리오 |
|---|---|---|---|
| 전화번호 | 실번호 수집 금지 | 국가코드·자리수·발신유형 같은 형태 특징만 | `010-0000-0000` |
| 계좌번호 | 실계좌 수집 금지 | “타인 명의 계좌 요구”, “기관 공식계좌 아님” 같은 행위 특징만 | `000-000000-00-000` |
| URL | S5만 격리 전처리 가능 | SHA-256, 호스트·경로 형태 특징, 탐지 기준일 | `.invalid` 또는 `example.com` |
| 인명·조직명 | 개인명 수집 금지 | 사칭 주체의 범주 | 역할명·가상기관 |

### 4.4 생성·검수 절차

1. 소스 담당자가 신규 공식 게시물과 이용조건을 확인한다.
2. `source_registry`에 URL, 제목, 기관, 게시일, 접속일, 라이선스 문구를 먼저 등록한다.
3. 원문에서 수법 사실만 `method_pattern`으로 구조화한다.
4. 합성기가 서로 다른 패턴 요소를 조합해 시나리오 초안을 만든다.
5. 자동 검사로 전화번호, 계좌번호, 활성 URL, 주민등록번호형 문자열, 원문 장문 중복을 차단한다.
6. 사람이 사실성, 저작권 비복제, 금융·개인정보 부재, 과도한 공포 유발 여부를 검수한다.
7. 통과한 시나리오만 `synthetic_scenario`에 넣고 `is_synthetic=true`와 출처를 화면에 표시한다.

### 4.5 갱신 주기

- 월 1회: KISA 보호나라와 방통위 스팸 관련 신규 공식 게시물 확인
- 분기 1회: 공공데이터포털의 수정일·행 수·이용허락범위 변경 확인
- 즉시 반영: 기관이 신종 수법 주의보를 낸 경우
- 삭제·격리: 이용조건 변경, 출처 삭제, 개인정보·실금융정보 혼입, 원문과 과도한 유사성이 발견된 경우

## 5. 확인 보류·미채택 후보

- **금융감독원 보이스피싱지킴이**: 조사 환경의 브라우저 보안 정책으로 금융감독원 도메인의 상세 페이지에 직접 접속할 수 없어 게시판 URL과 저작권 문구를 검증하지 못했다. 추정 URL은 기록하지 않았으며 이번 확정 목록에서 제외했다. S1은 금융위 페이지에 게시된 금융위·금감원 공동 자료라서 별도로 채택했다.
  - **[리뷰어 확인 2026-07-24]** 게시판 실존은 검색으로 확인 — 피해사례 목록
    `https://www.fss.or.kr/fss/bbs/B0000059/list.do?menuNo=200359`, 체험관 "바로 이 목소리"
    `.../bbs/B0000203/...` (menuNo=200686). 단, fss.or.kr 전체가 JS 렌더링이라 서버사이드
    fetch로는 본문·저작권 정책(menuNo=200701) 내용 추출 불가 — 도구 환경의 한계이지 소스
    부재가 아님. **M단계에서 실브라우저로 저작권 문구 확인 후 승격 여부 재판정** (그 전까지
    수법 DB 소스로 인용 금지 유지, S1·S2로 충분히 커버됨).
- **경찰청 누리집의 수법 안내·보도자료**: 검색 결과에서는 관련 자료와 공공누리 표기가 확인됐지만 상세 페이지 직접 접속 검증이 완료되지 않아 원 경찰청 URL은 제외했다. 대신 제공기관이 경찰청으로 명시되고 이용허락범위가 확인된 S4·S6·S7·S9를 채택했다.
- **KISA 불법스팸대응센터의 개별 월별 현황 페이지**: 개별 상세 페이지가 직접 접속 단계에서 404 또는 보안 차단되어 확정 소스로 넣지 않았다. 월별 공개 사실과 공공누리 조건을 직접 확인한 방통위 S3만 사용한다.
- **KAIT 별도 자료**: 조사일 기준으로 스팸·스미싱 사례와 페이지별 이용조건을 함께 확인할 수 있는 공식 상세 페이지를 확정하지 못했다. 라이선스 추정 없이 제외한다.

## 6. 최종 결정

1. MVP 수법 DB의 본문은 S1·S2에서 추출한 사실 패턴을 기반으로 **전면 합성**한다.
2. 유형 분류와 위험도 보정은 S4·S6·S7의 공개 집계 통계를 사용한다.
3. S3은 스팸 채널 추세의 보조 근거로 사용한다.
4. S5는 활성 URL을 저장·노출하지 않는 해시 기반 보조 탐지로만 검토한다.
5. S8의 실제 피해 기반 금융데이터는 사용하지 않는다.
6. 모든 사례는 실명·실번호·실계좌·활성 악성 URL 없이 `is_synthetic=true`로 제공하고, 출처와 합성 사실을 함께 표시한다.
