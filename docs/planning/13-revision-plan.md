# 개정 라운드 1 — 아키텍처 결정 (12-human-review 반영)

작성: 2026-07-24. `12-human-review.md`의 지적을 수용해 오케스트레이터(Claude)가 내린 확정
결정. `10-proposal-draft.md`·`11-spec-draft.md` 개정은 이 계약을 따른다. 항목 번호는 이후
추적용(D1~D17).

## D1. 긴급 우회로 (최우선)

첫 화면 최상단에 상태 질문 배치: **"돈을 보냈거나, 앱을 설치했거나, 인증정보를 알려주셨나요?"**
해당 시 AI 판정과 무관하게 **결정적 규칙 기반 즉시 안전 카드**(금융회사 대표번호·112 우선)를
먼저 표시하고, AI 분석은 병렬로 진행해 행동 카드 아래에 보조 근거로 붙인다. F-05는 "판정 후
분기"가 아니라 "첫 화면 긴급 우회로"로 재정의.

## D2. 피해 상태 스키마 + 조치 결정표

상태 필드: `transfer_state`, `device_compromise_state`(none/suspected_app/remote_control/
unknown), `credential_exposure_state`, `personal_data_exposure_state`,
`user_role`(self/family_proxy), `safe_device_available`. 명세에 **조합별 조치 결정표**를 포함:
각 행 = [상태 조합 → 1·2·3순위 행동, 금지 행동(do_not_show_when), 공식 출처, 템플릿 버전].
예: 악성 앱 의심 시 "감염 의심 기기에서의 금융앱 사용" 금지 행동 표시, 안전한 별도 기기 확인.

## D3. `completed` 폐기 → 행동 사실 원장

행동 상태를 사실 수준별로 분리: `viewed / dialer_opened / user_reported_connected /
user_reported_requested / receipt_confirmed / not_applicable / unknown`. 각 상태에
출처(`ui_event` | `user_statement`)를 함께 기록. 단일 "완료율" 지표 폐기 —
자동 측정은 `official_action_presented`·`dialer_opened`까지만, 연결·요청·접수는 사용자
확인값 또는 사용성 테스트 관찰로만.

## D4. 데이터 생명주기 통일 (핵심 구조 변경)

- **서버 DB·공개 상황실·집계 = 합성 사건 전용.** 사용자 자유 입력 사건은 서버에 저장하지
  않는다 (본문 없는 운영 메트릭만: 요청 수·지연·폴백 횟수).
- 사용자 사건의 진행 상태·판정 결과는 **브라우저 세션(sessionStorage)에만** 유지.
- **개인 상황실 뷰**: 심사위원/사용자는 자기 사건의 6단계 파이프라인 타임라인을 *자기
  브라우저 안에서* 실시간으로 본다(SSE 스트림은 응답 중에만, 저장 없음). 공개 `/room`은
  합성 시드 사건 전용으로 라벨 명시. → "내 사건이 상황실을 통과하는" 데모 경험은 유지하되
  동의 없는 공개·재식별 리스크 제거.
- `case_write_token`·서버 쓰기 API(answers/actions PATCH) 제거. PDF는
  `POST /api/v1/briefing.pdf`에 비식별 구조화 사건 JSON을 보내 즉시 생성·반환(무저장).
- PII 흐름 명세 추가: 기기 내 1차 가림 미리보기(사용자 확인) → 서버 2차 마스킹 → 모델 호출,
  각 구간 처리자·보관·로그 제외를 데이터 흐름 표로 명시. 실제 메시지 입력은 "합성 샘플 기본,
  실제 입력은 가림 미리보기 후 선택" 플로우로.

## D5. 평가셋 분리 (36건 공통 기반 폐기)

`데모 3건` / `개발·회귀 40건` / `비공개 홀드아웃 40건` / `적대 입력 20건` 분리(합성 생성,
수법 6종×정상·불확실 포함). 안전성 리포트는 **홀드아웃+적대셋 결과만** 게시: 분모, 클래스별
건수, 95% 구간, 실패 사례 범주, 라벨링 절차, "프롬프트 튜닝 노출 없음" 명시. 지표:
수법별 FN/FP/유보, unsafe action rate, citation validity, PII leakage, template boundary
violation, injection attack success rate, fallback correctness.

## D6. must 축소 — 코어 여정 중심

- **must**: 입력(F-01, 합성 샘플 기본) / 긴급 우회로(F-05 재정의) / 근거 판정(F-03,
  "근거 충분도"로 개칭) / 확인 질문(F-04) / 조치 결정표 기반 행동 카드+사실 원장(F-06) /
  고정 문구(F-07, 3영업일 후속 절차 포함) / 신고 준비 브리핑 PDF(F-08 개칭) / 고령자
  모드(F-10) / 개인 파이프라인 타임라인(F-13 재정의: 자기 사건, 로컬) / 공개 상황실 합성
  시드 뷰(F-12 축소: 합성 전용 라벨) / 안전성 리포트(F-20, D5 반영) / 신뢰 장치(F-21) /
  agent 레이어 축소판: 판정 API(F-16, 쿼터·남용 대응 명세)+MCP(F-18, 동일 도구)+llms.txt
  (F-19)
- **nice**: OCR(F-02), 가족 요약(F-09), 음성 읽기(F-11), 합성 대시보드(F-15, "합성 평가
  결과 전용" 라벨)
- **제거**: 관계 그래프(F-14 — 사건 타임라인으로 대체), 사건 쓰기 API(F-17의 PATCH·answers)
- agent 레이어를 유지하는 이유: 사용자 확정 요구(agent-friendly)이자 차별화 쐐기. 단
  남용 표면 통제(쿼터, CORS, 오류 본문 정책, 남용 탐지, 목적 제한 고지)를 명세에 포함.

## D7. 용어 전면 교체 (전 문서 일관)

## D8. 훅·데모 재배치

훅 문장은 §2에 1회만. 30초 와우 = 판정 카드가 아니라 **같은 합성 메시지의 "송금 전 vs 송금
직후" 행동 재구성을 나란히 15초 안에** 보여주는 장면. 2분 데모 = `합성 메시지 → 상태 전환
→ 즉시 행동·고정 문구 → 브리핑 PDF → 안전성 실패 사례 1건 공개 화면`. `/developers`는 Q&A
백업으로 강등. 실제 메시지 입력 권유는 "가림 미리보기 후 선택"으로 표현 수정.

## D9. 문제 정의 좁히기

"서로 연결되어 있지 않다" → **"소비자 화면에서 상태별 순서, 한 번 입력한 사건 맥락, 기관
전달용 브리핑, 사용자 확인 상태가 하나의 연속 경험으로 제공되지 않는다"**. 112 통합신고의
기관 연계(2023~)는 인정하고 인용한다.

## D10. 주고객 선언

v1 주고객 = **송금했거나 앱·인증정보를 이미 건드린 직후의 금융소비자** (송금 전 의심자는
진입 경로, 가족은 보조 사용자, AI 에이전트는 유통 채널·확장으로 재배치). 양식 항목 3의
"특정 금융 고객 선택"에 이 선언을 명시.

## D11. 경쟁표 재설계

자사 행을 `계획/구현/배포 검증` 상태로 표시(전부 O* 금지). 결합 행 분리(서비스 개별 행).
축 교체: `판정 / 긴급 첫 행동 / 기관 전달 준비 / 사용자 확인 상태 / 실제 처리 권한 / 무설치
웹`. "실제 처리 권한"에서 골든타임은 X(없음)를 정직하게 표시 — 처리 권한은 금융회사·경찰.

## D12. 기대효과 재구성

본문 = 직접 측정 KPI만: 첫 안전 행동 노출 시간(초), 오행동률, 브리핑 필수 필드 충족률,
상담 시뮬레이션 재질문 수. **126억 원·상담 인력 1명분은 본문에서 제거**하고 "정책 민감도
예시(제품 효과 주장 아님)"로 부록·각주 격리. 2021 설문 일반화 금지(01 문서 개정 반영).

## D13. 사업화 구체화

첫 구매자 1개 선정: **은행 콜센터 사기 상담 앞단 사전 브리핑** — `사용 지점(상담 연결 전
대기 화면) → 수신 데이터(비식별 구조화 브리핑 필드 목록) → 승인 책임(은행 소비자보호·준법)
→ KPI(초기 정보 수집 시간·재질문 수) → 도입 전제(모델 위험관리·개인정보 처리 위탁 계약·
템플릿 승인·감사 로그)`를 한 표로. 지자체·agent API는 확장 한 줄로 축소.

## D14. §7 한계 고지 압축

본문에는 3대 위험(오분류 / 개인정보 / 외부 처리 상태)만 [위험→기술 통제→실측 결과(M단계
기입)] 표로. 전체 매트릭스는 부록 표기. 방어 문장 빈도 축소 — "무엇을 잘하는지"가 먼저.

## D15. 규제 문구 레지스트리

고정 템플릿마다 `공식 출처·시행일·검수일·재검토 예정일·변경 이력` 메타데이터. 지급정지
전화 신청 후 **3영업일 이내 서면 신청** 후속 의무를 행동 카드·브리핑 PDF에 포함.

## D16. QA 출처 검증 강화

`source_refs`는 이번 요청에서 검색된 허용 ID 집합과 결정적 대조. 근거 라벨은 "공식 확인"이
아니라 **"공개 수법 패턴과의 유사 신호"**. 사람 표본 검수(출처가 실제로 문장을 지지하는지)를
M단계 인수 기준에 추가.
