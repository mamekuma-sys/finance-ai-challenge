## 지금 유효한 계약은 무엇인가 (진입점)

**구현 계약은 `41-spec-draft.md` 하나다.** 기능 ID·`CaseState` 스키마(§4.2)·
관문 엔진 총함수(§4.1)·규칙셋(§4.3)·인수 기준(§9)을 임의 해석·변경하지 않는다.

`31`은 컨셉 확정 근거, `32`는 관문 ①의 규칙 원본이며 둘 다 `40`·`41`의 상위 계약이다.

## 검증 루프 (two-way)

초안 완성 시마다 ① **AI 관점** — judge 스킬(루브릭 채점) ② **사람 관점** — 휴먼 심사위원
페르소나 리뷰(30초 훅·사내 공유 가능성·본선 경쟁력·과장/한계). 두 관점 모두 통과할 때까지
반복한다. 골든타임 루프의 실적: 패널 5라운드 + 개정 계약 r1~r6 → P 92.8.

현재 라운드 이력: `010-P` 82.5 → `011-P` 91.9 → `012-P` **93.8**.

## 원칙

- 기능명세서에 적은 기능은 배포 URL에서 **전부 실제 작동**해야 한다.
  제출 PDF에는 `작동확인` 상태의 기능만 기재한다(양식 지시: 미구현·예정 제외).
- MVP는 **심사위원이 30초 안에 핵심 가치를 체험**할 수 있게 설계한다.
- 수치는 `docs/research/19-verify-final3.md`·`04-verification-digest.md` 정정표 통과분만
  인용하고 **기간·주체·출처를 병기**한다.
- **법령 인용은 시행령까지 대조**한다. 원문은 법제처 Open API로 취득한다
  (`law.go.kr/DRF/lawService.do?OC=test&target=law&MST=<번호>&type=XML`).
