## 1. 개요

### 1.1 한 줄 정의

무단이체·명의도용·사기 피해자가, 은행이 **기억으로 답하라고 요구하는 항목**을 자기 기기에
남아 있는 **기록으로** 답하고, **어느 제도의 문이 열려 있는지와 그 문들 사이의 순서**를
신청 전에 확인하는 무설치·무로그인 웹 서비스.

### 1.2 사용자 유형

| 유형 | 설명 | 진입 |
|---|---|---|
| **U1 피해자** | 무단이체·명의도용·기망당한 직접 이체 피해 개인(개인사업자 포함) | 무로그인 |
| **U2 심사위원·첫 방문자** | 합성 사건으로 60초 체험 | 무로그인 |
| **U3 은행 심사역(뷰)** | 같은 사건을 심사 큐·쟁점으로 보는 대칭 화면 | 무로그인(데모 뷰) |
| **U4 에이전트** | 이용자를 대신해 조회·계산을 수행하는 AI 에이전트 | 무인증 읽기·계산 API |

### 1.3 접근·처리·저장 원칙 (위반 시 릴리스 차단)

1. **무로그인·무설치.** 데모 계정 자체가 필요 없다
2. **개인 사건 데이터 서버 무저장.** 브라우저 세션에만 존재. 요청 본문 무로깅
3. **판정은 생성형 AI 밖.** 관문 판정·경로 배정·과실 평가는 결정적 규칙 엔진이 수행
4. **확률·승산·예상 금액을 출력하지 않는다.** 응답 스키마에 해당 필드를 두지 않는다
5. **제출·대리를 하지 않는다.** 제출 API가 존재하지 않는다
6. **모든 규범 주장에 조문·공개자료 인용을 강제**한다. 인용 없는 주장은 렌더링 차단
7. **실금융데이터·개인정보 미사용.** 시연 데이터는 전부 합성

## 4. 계약

### 4.1 관문 엔진 (총함수)

```
investigate(state: CaseState, ruleset: Ruleset) -> Verdict
```

**총함수 요건**: 모든 입력에 대해 예외 없이 결과를 반환한다. 판정 불가는 예외가 아니라
`undetermined` + 사유로 표현한다. **동일 입력 → 동일 출력**(F-16 재현성 검사 대상).

**6단계** (기존 `engine.ts` 구조 승계):
1. 상태 정규화 · 필수 필드 결측 검사(fail-closed)
2. 규칙 매칭 (`Rule.match(state) -> boolean`)
3. 행동·판정 병합 (`MERGE_KEYS`)
4. **경로 의존 해소** — 순서 제약을 적용해 닫힌 경로를 제거 (신규)
5. 출처 합집합 · 인용 부착 (인용 없는 항목은 산출물에서 제외)
6. 우선순위 정렬 · 기한 시계 산출

### 4.2 `CaseState` (사건 상태 스키마)

| 필드 | 타입 | 용도 |
|---|---|---|
| `transfer_actor` | `self` \| `third_party` | §2②가·나목 분기 |
| `pretext` | `goods` \| `service` \| `loan` \| `other` | §2② **단서** 분기 |
| `fund_movement` | `transfer` \| `handover` \| `withdrawal` | 가·나 ↔ 다·라목 분기 (신청 주체 결정) |
| `account_balance_band` | `at_or_below_threshold` \| `above` | §5①6호 (**금액을 입력받지 않고 구간만**) |
| `litigation` | `{filed: bool, timing: before_freeze \| after_freeze, type}` | §4의2·§5①1~5호 |
| `claim_amount_band` | 구간 | 금소법 §42 / 소액사건 구분 |
| `is_general_consumer` | bool | 금소법 §42 |
| `dates` | `{incident, freeze_notice, public_notice}` | 기한 시계 |
| `facts[]` | `{time, actor, action, source, confidence_label}` | 타임라인 · 질문 매핑 |
| `evidence_gaps[]` | `{question_id, issuing_route}` | 결손 · 발급 경로 |

> `confidence_label`은 **`stated` / `recorded` / `absent`** 세 값이며 **확률이 아니다.**
> 금액은 **구간(band)만** 다룬다 — 원금액을 받지 않으므로 금액 산출이 구조적으로 불가능하다.

### 4.3 규칙셋 `R-01 ~ R-04`

| ID | 규칙셋 | 근거 | 규칙 수(목표) |
|---|---|---|---:|
| **R-01** | 관문 ① 제외사유 | 공개 신고서식 12~15종 | ~18 |
| **R-02** | **경로 배정 + 순서 제약** | 통신사기피해환급법 §2·3·4·4의2·5·6·7·8·9·10 + 시행령 §3의2·6·8 | ~25 |
| **R-03** | 관문 ② 과실 | 전자금융거래법 시행령 제8조 4개 호 | ~14 |
| **R-04** | 절차·기한 | 금융소비자보호법 §36·42 + 시행령 §36, 소액사건심판규칙 §1의2 | ~10 |

**모든 규칙은 `{id, match, actions, citations[], effective_date}`를 갖는다.**
`citations`가 비면 빌드 실패(F-19).

### 4.4 A-면 계약 (F-12·F-13·F-14)

**열린 것 — 읽기·계산 전용, 무인증**

| 엔드포인트 | 반환 |
|---|---|
| `GET /api/scenarios` | 합성 사건 목록(`is_synthetic: true`) |
| `GET /api/scenario/{id}` | 사건 상세 + 타임라인 이벤트 |
| `POST /api/investigate` | `CaseState` → `Verdict`(경로 집합·쟁점·결손·인용·기한) |
| `POST /api/counterfactual` | `CaseState` + 변경 1건 → 변경 전후 `Verdict` **차이** |
| `GET /api/rules` | 규칙셋 전문 + 조문 인용 (**감사용**) |
| `GET /api/eval` | 하네스 결과(오분류율 2축, 실패 사례) |

**닫힌 것 — 존재하지 않는다**

- 제출·신청 엔드포인트 **없음** · 쓰기 엔드포인트 **없음**
- 응답 스키마에 확률·승산·예상 금액 필드 **없음**
- 개인정보 수집 **없음** · 요청 본문 로깅 **없음** · 서버 저장 **없음**

`llms.txt` 필수 문구: **"이 서비스는 대신 제출하지 않습니다. 최종 판단과 제출은 사람이 합니다."**

### 4.5 증적 패키지 (F-10)

PDF와 JSON은 **같은 데이터에서 생성**하며 JSON 스키마는 `/api/investigate` 응답과 동일하다.
포함: ① 사건 타임라인 ② 질문↔기록 대응표 ③ 경로 보드(열림/닫힘·사유·기한) ④ 쟁점별
근거/반증/결손 ⑤ 결손 발급 경로 ⑥ 인용 전문 ⑦ **"예비 평가이며 제출용 서식이 아님" 고지**.

## 5. 데이터 모델과 생명주기

| 영역 | 내용 | 보존 |
|---|---|---|
| **Neon Postgres** | 합성 시나리오 120건, 규칙셋, 조문 인용, 하네스 결과 | 영구(공개 데이터만) |
| **브라우저 세션** | 이용자가 입력한 사건 사실·타임라인 | **탭 종료 시 소멸** |
| **서버 메모리** | 요청 처리 중 `CaseState` | 응답 후 폐기, 로깅 없음 |

**합성 데이터 규칙**: `is_synthetic=true` · 전화번호 `010-0000-0000` · URL `.invalid`/`example.com` ·
실제 사건·인물과 무대응 · 화면 배지 표기.

**평가셋 분리**: 하네스 120건 중 **홀드아웃 40건은 개발 중 열람 금지**. 판정 규칙은

## 6. AI 파이프라인 명세

### 6.1 처리 순서 (기획서 §5.3의 7단계)

| # | 단계 | 실행 유형 |
|:-:|---|---|
| 1 | 입력 정규화 | **LLM** |
| 2 | 타임라인 구성 | LLM + 규칙 |
| 3 | 질문 매핑 | **LLM** → 사람 확인 |
| 4 | 관문 판정·경로 배정 | **결정적 규칙** |
| 5 | 쟁점 보드 생성 (대립 3역 대조) | 규칙 + **LLM 서술** |
| 6 | 반사실 재계산 | **결정적 규칙** (4·5만 재실행, 1~3 재호출 없음) |
| 7 | 검증·출력 | 결정적 검사 |

### 6.2 자유 생성 허용·금지 구간

| 구간 | 자유 생성 | 근거 |
|---|:-:|---|
| 1·2·3단계 (사실 구조화·매핑) | **허용** | 비정형 입력 처리 |
| 5단계 심사역·소비자 논거 **서술** | **허용 (인용 강제)** | 대립 구조 |

| 금액·확률·승산 | **금지 (스키마에 필드 없음)** | FTC 사례 |

### 6.3 폴백

모델 장애 시 **1·2·3·5단계를 건너뛰고 4·6·7단계만으로 화면을 유지**한다.
합성 사건 경로(F-01~F-08, F-10)는 **모델 호출 없이 전부 작동**해야 한다 —
즉 **심사위원의 60초 경로는 모델 장애와 무관하다.**

### 9.2 릴리스 게이트 (F-19 — 하나라도 실패하면 배포 중단)

1. 확률·승산·예상 금액 표현이 산출물·응답 스키마에 **존재하지 않음**
2. 모든 규범 주장에 **인용이 붙어 있음** (`citations` 빈 규칙 0건)
3. 모든 법령 인용에 **시행일이 병기**되어 있고 **시행령 대조 기록**이 있음
4. **제출·쓰기 엔드포인트가 존재하지 않음**
5. `/my` 입력의 **서버 무저장·무로깅**이 네트워크 계측으로 확인됨
6. 동일 입력 반복 호출의 **출력 일치**(재현성)
7. 합성 사건 경로가 **모델 호출 없이** 전부 작동
8. 홀드아웃 40건 오분류율이 **사전 등록한 임계값 이하**
9. 배포 URL이 **무로그인 시크릿 창에서 열림**(배포 보호 해제 확인)
10. `llms.txt`·`/agent`가 응답하고, **에이전트 경로(§3.3)가 끝까지 완주**

### 9.3 v1 인수 기준

- T1·T2 전 기능 `작동확인`
- 60초 심사 경로(§3.2)가 **끊김 없이** 재현
- 에이전트 경로(§3.3)가 **외부 에이전트로 실측 완주**

- 기획서·기능명세서 PDF와 화면 **용어 일치**
