## 1. 서비스 명칭

### 「기록으로」 — 내 편의 사고조사실

- **한 줄 정의**: 무단이체·명의도용 피해자가 은행이 **기억으로 답하라고 요구하는 항목**을
  자기 기기에 이미 남아 있는 **기록으로** 답하게 하고, 배상 심사의 **두 관문을 신청 전에
  미리 통과시켜 보는** 무설치·무로그인 웹 서비스
- **서비스 약속**: *"내가 이 제도의 대상인가"* 와 *"은행이 무엇을 물을 것인가"* 를
  **신청서를 내기 전에** 알 수 있게 한다
- **권한 경계**: 조립까지만 한다. **신청·제출은 소비자가 은행 앱·창구로 직접 한다.**
  배상 여부·비율의 판정 권한은 금융회사와 금융감독원·법원에 있다
- **하지 않는 것**: 승산·확률·예상 배상금액을 출력하지 않는다. 대신 제출하지 않는다

## 2. 아이디어 기획 핵심내용(요약)

> **"상담 2,135건 → 신청 173건 → 배상 18건. 상담한 100명 중 1명 미만(0.84%)이 배상을 받습니다.
> 「기록으로」는 신청서를 내기 전에 두 관문을 미리 보여줍니다."**
> — 5대 은행, 2024-01~2025-08, 이인영 의원실이 금융감독원에서 제출받은 자료(2025-10-10 국정감사)

- **두 관문 구조**: ① **요건 관문** — 제외사유 대조(공개 서식 기준 12~15종).
  걸리면 즉시 **대체 경로**(통신사기피해환급법 환급 / 금융감독원 분쟁조정 / 민사)를 제시
  ② **과실 관문** — 전자금융거래법 시행령 제8조 4개 호별 쟁점 보드
- **핵심 전환**: 「기억으로 답하기 ↔ 기록으로 답하기」 — 공개 신고서식의 질문 항목에
  내 기기 기록(문자 원문·통화 기록·앱 설치 이력·거래내역·은행 알림)이 **사실로 꽂힌다**
- **와우 장면(쌍둥이 사건)**: 같은 피해금액·같은 겉보기 조건의 두 사건이 **요건 관문에서
  갈라진다.** 제3자 무단이체는 통과, 본인 직접 이체는 차단 — 그리고 차단된 쪽에 다른 문이 열린다
- **반사실 시뮬레이션**: 사실 하나(링크 클릭 여부·악성앱 설치 여부·이체 주체·경고 수신 여부)를
  바꾸면 두 관문과 쟁점 보드가 **즉시 재계산**된다 — *무엇이 결과를 가르는가*를 보여준다
- **핵심 산출물**: 화면이 아니라 **「증적 패키지」** — 사건 타임라인 + 질문↔기록 대응표 +
  쟁점별 근거·**결손 목록과 발급 경로** + 적용 조문 인용. **PDF와 JSON 동시 출력**
- **두 개의 입구**: 「준비된 사건으로 보기」(첫 방문자·심사위원, 30초 체험) /
  **「내 사건 넣기」**(문자 원문·통화 기록·거래내역을 붙여넣으면 **생성형 AI가 사건을 조립**
  → 사고 이후에 시작해도 작동하므로 **오늘 당장 사용 가능**)
- **대립 3역**: 소비자 측 조사관 / **은행 심사역 측**(제외사유·중과실을 찾는 역할) /
  조정관(다툴 지점만 남긴다) — **반대편을 먼저 써 보는 것이 이 서비스의 본질**
- **3면 구조**: 소비자 뷰 / **은행 심사역 뷰**(같은 사건이 심사 큐·쟁점으로 보임) /
  **에이전트 면**(§7)
- **처리 구조**: 관문 판정·과실 평가는 **생성형 AI 밖의 결정적 규칙 엔진**이 수행하고,
  생성형 AI는 비정형 기록의 구조화·매핑·서술에만 쓴다 → **같은 입력에 같은 출력(재현성)**
- **안전 장치**: 합성 사고 120건 정답 대조 **오분류율을 화면에 공개**, 모든 주장에 조문·공개자료
  **인용 강제**, 확률·금액 출력 금지 가드레일, 개인 사건 데이터 **서버 무저장**

## 3. 문제 정의 및 제안 배경

### 3.1 한 문장 문제 정의

> **한국의 배상 심사는 두 번 거른다. 신청의 34.7%는 「피해자가 직접 이체했다」는 이유로
> 심사에 들어가지도 못하고, 심사에 올라간 것도 대부분 「이용자 과실」로 끝난다.
> 두 관문의 규칙은 전부 공개돼 있는데, 그 규칙에 넣을 사실만 소비자 쪽에 없다.**

문제를 **피해 규모**가 아니라 **절차 구조**로 정의한다. 피해액은 우리 서비스의 시장이 아니다.

### 3.2 깔때기 — 하나의 출처·하나의 기간·하나의 모집단

5대 은행, **2024-01 ~ 2025-08**, 이인영 의원실이 금융감독원에서 제출받은 자료
(2025-10-10 국정감사 공개, [본문확인](https://www.joongangenews.com/news/articleView.html?idxno=456189)):

| 단계 | 건수 | 직전 단계 대비 | 무엇이 일어나는가 |
|---|---:|---:|---|
| 상담 | **2,135** | — | 은행에 물어본 사람 |
| ↓ 신청 | **173** | **8.1%** | **91.9%가 신청서를 내지 못했다** |
| ↓ 심사 제외 | **60** | 신청의 **34.7%** | 사유: **피해자 직접 이체 · 로맨스스캠 · 중고사기** |
| ↓ 심사 완료 | 92 | — | (잔여는 심사 진행 중) |
| ↓ 배상 | **18** | 심사완료의 **10.4%** | **상담 대비 0.84%** |

금액 기준으로도 같다 — 신청금액 6억 3,762만원 중 배상 **1억 4,119만원(22.1%)**.

> **이 깔때기의 가장 큰 손실 구간은 「상담 → 신청」의 91.9%다.** 여기서 사라지는 1,962명이
> 「기록으로」의 이용자다.

**미신청 사유의 근거 구분 (과장하지 않기 위해 분리한다)**

| 구분 | 내용 |
|---|---|
| **확인된 사실** | 상담 2,135건 중 신청은 173건이다(8.1%). 신청 단계에서 요구되는 것은 제외사유 12~15종 대조와 서식 p.3의 7개 항목 **기억 진술**이다(§3.3, 공개 서식 확인) |
| `[추론]` | 미신청 사유가 "대상 여부를 모르고, 입증 대상을 모르며, 기억으로 답해야 해서"라는 것은 **추론이다. 사유 분포를 집계한 자료는 확인되지 않았다** |
| **관측 가능한 대리 지표** | 2025년 은행 민원은 전체 −10.2%인데 **보이스피싱 관련만 +125.7%(+2,423건)**로 은행 민원의 **20.1%**를 차지한다(금융감독원) → 이 층은 은행에 **묻기는 하고 있다.** 상담 2,135건과 같은 방향의 관측치다 |

이 문서는 91.9%를 **"수요의 상한"이 아니라 "제도가 닿지 못한 구간의 크기"**로만 사용한다.

### 3.3 비대칭의 증거는 은행 자신의 공개 서식 안에 있다

공동개최사가 공개 배포 중인 **「전자금융거래 사고 피해 신고서」**(하나은행, 양식 5-99-0002,
2024-01 개정, 8쪽,
[원문 PDF](https://image.kebhana.com/cont/customer/customer07/customer0701/customer070106/__icsFiles/afieldfile/2024/06/12/5-99-0002.pdf) [8쪽 전량 파싱 확인])
— 이 문서는 **비대면 금융사고 책임분담기준의 공식 신청 양식**이며, 한 문서 안에 비대칭이 있다.

| 서식 위치 | 내용 |
|---|---|
| **p.3 — 소비자에게 요구** | 스미싱 링크 클릭 여부 / 악성앱 설치 여부 / 제3자에게 제공한 정보 6종 / 인터넷·폰·오픈뱅킹 **사용 경험 및 빈도** / 신분증 보관 방식 / **평상시 휴대전화 잠금 방식** / 접근매체 보관 방식 → **전부 기억으로 답한다** |
| **p.5~6 — 은행이 수집** | *"계좌(카드)거래내역, 전자금융 가입 및 거래내역 등 **보상절차를 위한 사실조사에 필요한 금융거래내역**"* → **은행이 자체 수집한다** |

> **심사의 재료는 은행 안에 있고, 소비자는 기억으로 진술한다. 그 진술이 곧 과실 판정의
> 근거가 된다.** 이 서식은 "공백의 증거"가 아니라 **은행이 이미 규격화해 둔 기준**이며,
> 「기록으로」는 그 기준 위에 소비자 쪽 준비 단계를 얹는다.

**그런데 그 질문들의 답은 이미 소비자 기기에 있다:**

| 서식이 기억으로 묻는 것 | 기기에 이미 있는 것 |
|---|---|
| 스미싱 링크 클릭 여부 | 문자함 원문 + 수신 시각 |
| 악성앱 설치 여부 | 설치 앱 목록 + 설치 시각 + 패키지명 |
| 제3자에게 제공한 정보 6종 | 통화 기록 + 문자 송신 이력 |
| 오픈뱅킹 사용 경험·빈도 | 은행 앱 알림 이력 + 거래내역 |
| 평상시 휴대전화 잠금 방식 | 기기 설정 |

**공백은 "증거가 없다"가 아니라 "심사 질문의 형식으로 번역할 수단이 없다"이다.**
따라서 이 서비스는 사고 이전 설치를 전제하지 않는다 — **사고 이후에 시작해도 작동한다.**

### 3.4 두 관문의 규칙은 공개되어 있다

- **관문 ① 요건** — 제외 대상: 피해자가 **직접 지급지시**한 거래(사기 피해 포함) / 가족·지인 거래 /
  접근매체 양도·양수 / 법인 피용자 거래 / **물품 구매 위장 사기(중고거래 등)** / **용역 위장
  사기(게임 아이템·채용 등)** / **몸캠피싱·로맨스피싱** / 전자금융업자(페이) 경유 / 대면 거래 /
  카드 물품구매 / 법적 분쟁 진행·판결 확정 / 이미 화해 성립
  ([우정사업본부 안내](https://www.epostlife.go.kr/IPUISB0404.do) 12종 [본문확인],
  하나은행 서식 15종). 신청기한 **사고 인지일부터 3년**, **여러 은행 피해 시 각 은행에 개별 접수**
- **관문 ② 과실** — **전자금융거래법 시행령 제8조**「고의나 중대한 과실의 범위」 4개 호:
  ① 접근매체 대여·사용위임·양도·담보 제공 ② 제3자의 무권한 이용을 알았거나 쉽게 알 수 있었음에도
  **누설·노출·방치** ③ 금융회사의 추가 보안조치를 정당한 사유 없이 거부 ④ 추가 보안조치 수단·정보의
  누설·노출·방치·대여·위임·양도·담보 제공
- **금융감독원 개선방안**(2025-05-29 발표): *"FDS 고도화나 대응조치의 미흡사항 등을 **객관적으로
  반영**하도록 책임분담 기준을 개선"*, 표준처리기한 신설(기존 평균 **116일**·최대 **307일** →
  **약 90일**), 비대면 배상신청 접근성 개선
  ([safetimes](https://www.safetimes.co.kr/news/articleView.html?idxno=230614) ·
  [etoday](https://www.etoday.co.kr/news/view/2474779) ·
  [edaily](https://www.edaily.co.kr/News/Read?newsId=05175846642237800) [3곳 본문 교차확인])
  - ⚠️ 취득 자료는 전부 *"3분기 중 시행 예정"* 예고 시점 보도이며, **시행 완료를 확인하는
    금융감독원 보도자료는 확인되지 않았다.** "발표"로만 인용한다

> **규칙은 공개돼 있고, 그 규칙에 넣을 사실만 소비자 쪽에 없다.** 이것이 제안의 전부다.

### 3.5 왜 지금인가

1. **개선방안은 처리기한을 다뤘지만 배제사유는 그대로다** — 「피해자가 직접 이체한 경우」는
   여전히 대상 밖이다(edaily 2025-07-24: *"직접 송금한 소비자는 배상 대상이 아니다"*).
   **관문 ①은 미해결 상태로 남아 있다**
2. **표준처리기한 약 90일이 은행에 압력이 된다** — 병목은 자료 보완 왕복이고,
   금융감독원은 **비대면 채널 배상신청 개선**을 함께 요구했다. 은행이 붙일 것을 찾는 시점이다
3. **무과실 배상책임 개정안이 국회 정무위 계류 중이다**(의안 2215538·2215547).
   통과하면 다툼이 **"은행이 중과실을 입증할 수 있는가"**로 이동하고, 그 다툼의 재료도
   똑같이 소비자 기기 안에 있다 → **같은 엔진이 두 법제를 모두 처리한다**(§4.4)
   - ⚠️ 통과된 의안 2216766은 **가상자산 관련이며 무과실·한도 조항을 포함하지 않는다.**
     "무과실 배상이 통과됐다"고 쓰지 않는다
4. **소비자가 요구하는 것과 공급되는 것이 어긋나 있다** — 한국은행 2024년 지급수단 이용행태
   조사(전국 만 19세 이상 **3,551명 대면**, 표본오차 ±1.69%p)에서 1순위는
   **"사고 발생 시 보상 등 소비자 보호 강화" 31.5%**이고, "이상거래 감지시스템"은
   **4위 8.6%**다. 은행권 AI 투자는 탐지·예방 축에 집중돼 있다
5. **민원이 이 축으로 쏠리고 있다** — 2025년 은행 민원은 전체 −10.2%인데
   **보이스피싱 관련만 +125.7%(+2,423건)**로 은행 민원의 **20.1%**를 차지한다(금융감독원)

### 3.6 특정 금융 고객·채널 선택 배경 (양식 요구 항목)

| 구분 | 선택 | 이유 |
|---|---|---|
| **1차 고객** | **"보이스피싱을 당했는데 마지막 이체 버튼을 내 손으로 누른 개인"** | 관문 ①에서 가장 많이 걸리는 유형이고(제외사유 1순위), 은행 창구·콜센터에 가장 많이 도착하며, **"당신은 이 제도 대상이 아니고 대신 이 경로가 있다"는 말을 어디에서도 듣지 못한다** |
| **2차 고객** | 무단이체·명의도용 피해 개인(개인사업자 포함) | 관문 ②에서 「이용자 과실」로 다투는 층. 심사 대상 기간은 2024-01-01 이후 사고 |
| **3차(양면)** | 은행 사고조사·책임분담 심사 담당자 | 표준처리기한 약 90일 준수 압력. 정리된 증적이 오면 사실조사 구간이 줄어든다 |
| **채널** | **무설치·무로그인 웹** | ① 사고 직후 앱 설치를 요구하면 이탈한다 ② 이 층은 고령·저디지털 이용자를 포함한다 ③ 심사위원이 URL만으로 즉시 체험할 수 있다 ④ 개인 사건 데이터를 **서버에 저장하지 않는** 설계가 가능하다 |
| **비채널** | **대화형 챗봇을 만들지 않는다** | 공동개최사의 대화형 AI 검색이 2026-06 기준 누적 500만 명 이용 규모다([뉴시스 2026-06-10](https://www.newsis.com/view/NISX20260610_0003663224) [본문확인]). 같은 UX를 다시 만드는 것은 열등한 중복이다 |

### 3.7 대조군 — 같은 문제를 다르게 다루는 제도

영국 지급결제감독기구(PSR) 의무배상 제도(2024-10-07 시행, 한도 £85,000):
**손실액의 89%(£243m)를 배상**하고, 소비자 주의의무 미달을 사유로 한 거절은 **2~3%**다
(청구 약 352,000건, 2024-10~2025-12,
[PSR 대시보드](https://www.psr.org.uk/information-for-consumers/app-scams-reimbursement-dashboard/) [본문확인]).
근거 규범은 **입증책임을 전적으로 지급기관에 지우고**(SR1 소비자주의기준 가이던스 §1.6),
**정형화된 문구 경고로는 거절할 수 없으며 개입은 소비자·사기유형·거래별로 개별적이어야 한다**(§1.10).

> 한국의 깔때기(상담 대비 배상 0.84%)와 영국의 89%를 나란히 놓는 것이 이 제안의 배경이다.
> **"은행이 어떤 경고를 언제 어떻게 했는가"가 이미 규제 판정 요소인 나라가 있다** —
> 그래서 증적은 소비자 쪽에서도 의미를 갖는다.

## 4. 서비스 컨셉 및 차별성

### 4.1 재현하는 것은 기능 하나가 아니라 **부서 하나**

「기록으로」는 은행의 **「전자금융사고 조사」 + 「비대면 금융사고 책임분담 심사」** 업무를
**소비자 쪽에서 대칭으로** 세운다. 상상한 부서가 아니다 — 실제 업무 명칭이다
(하나은행 「전자금융거래 사고 피해 신고서」 / BNK부산은행 「비대면 금융사고 조사 신청 안내」 /
KB국민은행 「전자금융사고 조사신청서」).

| 단계 | 은행 부서가 하는 일 | 「기록으로」가 하는 일 | 소비자가 지금 볼 수 있는가 |
|:-:|---|---|---|
| 1 | 요건 심사 — 제외사유 대조 | **관문 ① 시뮬레이션** + 걸리면 **대체 경로** 제시 | 종이 체크리스트로만 |
| 2 | 행동 사실조사 — 소비자 진술 확보 | **기억↔기록 전환** — 기기 기록을 질문 항목에 매핑 | **기억으로 쓴다** |
| 3 | 금융거래 사실조사 — 은행 자체 수집 | 같은 항목을 **소비자 쪽에서도** 세운다 | 아니오 |
| 4 | 이용자 과실 평가 — 시행령 §8 4개 호 | **관문 ② 쟁점 보드** — 호별 근거·반증·결손 | 아니오 |
| 5 | 금융회사 예방노력 평가 | 은행이 무슨 경고를 언제 했는지도 **증적 대상** | 아니오 |
| 6 | 비율 결정 → 통보 → 이의 | **증적 패키지 출력** + 기한 시계(3년/약 90일/보완) | 결과 숫자만 |

**6단계가 한 부서 안에서 돌고 단계마다 근거 규범이 다르다.** 그리고 2단계와 3단계 사이의
비대칭이 정확히 우리가 들어가는 자리다.

### 4.2 기존 금융 앱·서비스 대비 차별성 (4개 층 조사)

`../research/15-concepts-bank.md` 「기존 서비스 조사 기록」에 **공공 / 공동개최사 자사 /
민간·개인 / 해외** 4개 층 전수 조사표(URL·본문확인 표기 포함)가 있다. 요지:

| 층 | 이미 있는 것 | 「기록으로」와의 관계 |
|---|---|---|
| **공공** | 금융감독원 개선방안이 **비대면 신청 시스템 개선을 은행에 권고**. 각 사가 대상·서류·제외사유·기한을 **텍스트와 종이 서식으로 고지**. 금융감독원 민원조회는 **결정 이후** 단계 | **신청 창구를 새로 만들지 않는다.** 신청 **이전**의 준비 단계에 들어간다 |
| **공동개최사** | 8쪽 규격 신고서식(제외대상·행동설문·첨부 8종)이 **이미 규격화·공개**. 사전예방형 보안점수 서비스, FDS 성과 공시, 대화형 AI 검색 | **자사 자산 위에 얹는다.** 보안점수는 관문 ②의 예방노력·과실 축과 잇고, FDS 성과는 개선방안이 명시한 "예방 노력" 반영 축과 잇는다 |
| **민간·개인** | 무료·무로그인 해설 콘텐츠(중과실 3유형·절차·서류·사례), 법무법인 블로그, 판례 DB(casenote·lbox) | 전부 **읽는 문서**다. **자기 사건을 넣어 사실이 꽂히는 구조는 이번 조사 범위에서 확인되지 않았다** |
| **해외** | **Refundee**(영국 FCA 등록 CMC, 누적 £140m 회수, 성공보수 15~25%+VAT) 등 인간 조사관 유료 대행. **Resolver**는 무료지만 *"청구의 당부를 평가하거나 결과를 예측하지 않는다"*고 스스로 명시 | 해외에 동종 유료 서비스가 존재하므로 **"국내 최초·유일" 표현은 사용하지 않는다.** 경계가 다르다 — 그쪽은 **거절 이후** 대응, 「기록으로」는 **신청 이전** 준비. 무료·셀프서비스 |

### 4.2.1 기능 단위 대비표 (양식 요구 — "기존 금융 앱 대비")

`○` 제공 · `△` 부분·정적 제공 · `×` 이번 조사 범위에서 확인되지 않음

| 기능 | 은행 앱·안내 페이지 | 금융감독원 채널 | 민간 해설 콘텐츠 | 해외 유료 대행 | **「기록으로」** |
|---|:-:|:-:|:-:|:-:|:-:|
| 제외사유 **고지** | ○ (종이 서식·텍스트) | △ | ○ | ○ | ○ |
| **내 사건에 제외사유를 대조해 결과를 보여줌** | × | × | × | ○ (사람이 유료 평가) | **○** |
| 제외 판정 시 **대체 경로 + 각 기한 제시** | × | △ (개별 안내) | × | △ | **○** |
| 서식 질문 항목 제시 | ○ (기억 진술 요구) | × | ○ | ○ | ○ |
| **기기 기록을 질문 항목에 사실로 매핑** | × | × | × | △ (사람이 수집) | **○** |
| 시행령 §8 호별 **쟁점 보드**(근거·반증·결손) | × | × | × | ○ (유료 리포트) | **○** |
| **결손 항목의 발급 경로** 제시 | △ (첨부서류 목록) | × | △ | ○ | **○** |
| **사실 하나를 바꿨을 때의 반사실 재계산** | × | × | × | × | **○** |
| 심사 진행 상태 조회 | ○ | ○ (결정 이후) | × | ○ | × (은행 채널로 위임) |
| 배상 결정·비율 판정 | ○ (권한 보유) | ○ (분쟁조정) | × | × | **× (권한 밖 — 하지 않는다)** |
| 대신 제출·대리 | — | — | × | ○ | **× (하지 않는다)** |
| 승산·예상 금액 제시 | × | × | × | △ | **× (하지 않는다)** |
| 비용 | 무료 | 무료 | 무료 | **성공보수 15~25%** | **무료** |
| 이용 시점 | 신청 **이후** | 결정 **이후** | 상시(읽기) | 거절 **이후** | **신청 이전** |

> 표의 마지막 두 줄이 좌표를 확정한다 — **무료이면서 신청 이전 단계**인 칸은
> 이번 4개 층 조사에서 「기록으로」 외에 확인되지 않았다.
> 그리고 **하지 않는 것 3줄(판정·대리·승산)이 규제 방어선을 겸한다**(§4.3).

**차별점 3가지로 압축하면:**
1. **신청 전 단계** — 기존 수단은 전부 신청 이후(창구·심사·민원조회) 또는 거절 이후(대행)다
2. **관문 ①을 먼저 보여준다** — 34.7%에게 *"당신은 대상이 아니다, 대신 이 경로가 있다"*를
   신청서 작성 전에 말해 주는 수단은 조사 범위에서 확인되지 않았다
3. **출력이 문서가 아니라 상태다** — 사실이 꽂히면 채워지고, 비면 결손으로 남고,
   하나를 바꾸면 전체가 재계산된다

### 4.3 「기록으로」가 하지 않는 것 — 설계 원칙이 곧 방어선

| 하지 않는 것 | 근거 |
|---|---|
| 승산·확률·예상 배상률·예상 금액 출력 | 미국 FTC가 "AI가 변호사를 대체한다"는 주장에 **$193,000 지급·2025-02 최종명령**을 부과했다. 문제는 성능이 아니라 **검증되지 않은 판정 능력을 단정적으로 제시한 것**이었다 |
| "AI가 판정한다·결정한다"는 서술 | 「금융분야 AI 가이드라인」(2026-06-22 시행) **제3원칙 보조수단성** — 최종 의사결정과 책임은 사람이 수행한다. **AI는 근거를 모아 제시하고 결정은 사람이 한다** |
| 대신 제출·대리·알선 | 변호사법 제109조·제34조, 행정사법 제3조 제1항 |
| 대화형 챗봇 | §3.6 비채널 |
| 체크리스트 문서 생성 | 공개 신고서식이 이미 그것이다. 다시 만들면 열등한 복제품이 된다 |
| "국내 최초·유일" 표현 | §4.2 해외 층 |
| 특정 금융회사의 배상 실적 지목 | 대외 문서에는 **은행권 전체값만** 사용한다 |

용어도 이 원칙에 맞춘다: **`근거 충분도`**(확률이 아니다) / **"예비 평가"** /
**"행동 이벤트 이력(내 기기 보관)"**.

### 4.4 하나의 엔진이 두 법제를 모두 처리한다

화면 상단의 **「무과실 배상 개정안 적용」** 토글을 켜면 같은 사건·같은 증적으로 쟁점 보드가
재배열되고, 물음이 바뀐다:

- **현행**: *"이 사건이 제외 대상인가 / 이용자 과실이 있는가"*
- **개정 후**: *"은행이 중과실을 입증할 수 있는가"* — 입증책임이 이동하고,
  같은 증적이 **소비자의 방어 자료**로 다시 배치된다

이 설계는 **제도 변화를 리스크가 아니라 기능으로 흡수한다.** 개정안이 통과되어도 서비스는
소멸하지 않고 역할이 이동한다(한도 초과분·중과실 다툼·시행 전 공백 구간).

### 4.5 체험 시나리오

첫 화면에 **입구가 두 개**다. 로그인·설치가 없다.

| 입구 | 대상 | 성격 |
|---|---|---|
| **(A) 준비된 사건으로 보기** | 처음 방문한 사람·심사위원 | 합성 사건 카드 클릭 → 30초 안에 핵심 가치 체험 |
| **(B) 내 사건 넣기** | 실제 피해자 | 문자 원문·통화 기록·거래내역을 **붙여넣으면 사건이 조립된다** — **생성형 AI가 작동하는 지점**(§5.2 역할 1) |

#### (A) 30초 — 쌍둥이 사건

| 구간 | 화면에서 일어나는 일 |
|---|---|
| **0~6초** | 사건 두 개가 나란히. 겉보기 조건이 같다. **A**: 원격제어앱 설치 → 제3자가 4,800만원 무단이체 / **B**: 기관 사칭 전화 → **본인이 직접** 4,800만원 이체 |
| **6~14초** | 두 타임라인이 **동시에 초 단위 재생**. 이벤트가 쌓이고, 우측에 공개 신고서식 질문 7장이 회색 카드로 대기 |
| **14~20초** | **「관문 ①」이 내려온다.** A는 초록으로 열리고, **B는 붉게 닫힌다** — *「피해자가 직접 지급지시한 거래」 제외*. **"신청 173건 중 60건(34.7%)이 여기서 멈춥니다"**. 그리고 **B에게 다른 문이 열린다** — 환급법 / 분쟁조정 / 민사, 각 기한 시계와 함께 |
| **20~26초** | A로 이동, **「기억으로 답하기 ↔ 기록으로 답하기」** 토글. 회색 물음표에 타임라인 이벤트가 꽂히고 근거 카운터가 **0 → 11**, **채워지지 않은 2장이 붉게 남는다 = 지금 확보할 증거 + 발급 경로** |
| **26~30초** | **반사실 슬라이더** — *"링크를 클릭하지 않았다면"*을 켜면 시행령 §8 제2호 쟁점이 재배열되고 **어떤 사실 하나가 심사를 가르는지**가 보인다 |

#### 30~60초 — 반대편을 본다 (양면성 실물 증거)

| 구간 | 화면에서 일어나는 일 |
|---|---|
| **30~40초** | **「은행 심사역 뷰」** 토글. 같은 사건이 심사 큐 화면으로 바뀌고, **생성형 AI가 은행 심사역 측 논거를 먼저 쓴다**(§5.2 역할 3) — *"시행령 §8 제2호(누설·노출·방치) 해당 주장 가능 · 근거 2건 · 소비자 측 반증 2건 확보 · 결손 1건"*. 각 주장에 조문과 공개자료가 **인용으로 붙는다** |
| **40~50초** | **「내 사건 넣기」** — 합성 문자 원문 3줄을 붙여넣으면 `{시각, 행위자, 행위, 출처}` 이벤트로 **조립되어 타임라인에 삽입되고**, 관문·쟁점 보드가 재계산된다. **이 경로가 "오늘 당장 쓸 수 있다"의 실물 증거다** |
| **50~60초** | **「무과실 배상 개정안 적용」** 토글 → §4.4 / **「평가 하네스」** — 합성 120건 대조 **오분류율**과 가드레일 차단 사례를 화면에서 확인 |

> **첫 30초에 상태가 네 번 갈라진다**: 관문① 통과↔차단 / 기억↔기록 / 사실 하나의 반사실 /
> 소비자↔심사역. **확률도 금액도 출력하지 않는다.**
> **그리고 40~50초 구간에서 심사위원이 직접 텍스트를 넣어 생성형 AI의 작동을 확인한다** —
> 이 서비스에서 AI를 제거하면 (B) 입구가 사라지고, 실제 피해자는 사건을 손으로 다시
> 입력해야 한다. 즉 **데모는 남지만 서비스는 성립하지 않는다.**

### 5.2 생성형 AI의 역할 — 무엇에 쓰고 무엇에 쓰지 않는가

**핵심 설계**: 판정은 생성형 AI 밖의 결정적 규칙 엔진이 하고, 생성형 AI는 **비정형을 구조화하고
근거를 붙이는 데만** 쓴다. 이유는 두 가지다 — ① 규범이 결정적이라 모델 안에서 굴리면
**재현성**이 깨진다 ② 재현성 없는 판정은 §4.3의 규제 리스크로 직결된다.

| # | 생성형 AI가 하는 일 | 입력 → 출력 | 왜 AI가 필요한가 |
|:-:|---|---|---|
| 1 | **비정형 → 사건 타임라인 구조화** | 문자 원문·통화 기록·앱 알림·거래내역 텍스트 → `{시각, 행위자, 행위, 출처}` 이벤트 배열 | 소비자가 가진 것은 서식이 없는 조각들이다. 규칙으로는 파싱 불가 |
| 2 | **질문 ↔ 사실 매핑** | 서식 질문 항목 + 이벤트 배열 → 항목별 답변 후보 + **근거가 된 이벤트 인용** | 자연어 질문과 사실의 의미적 연결. 매핑 결과는 사람이 확인·수정한다 |
| 3 | **대립 역할 서술** | 사건 상태 → **은행 심사역 측 논거**(제외사유·중과실 주장)와 소비자 측 반론을 각각 서술 | 한 방향 요약은 안심시키고 실제 심사에서 진다. **반대편을 먼저 써 보는 것이 이 서비스의 본질** |
| 4 | **결손 안내문 조립** | 결손 항목 → 발급 경로 안내(통신사 수신내역·통화기록·앱 설치 이력·거래내역·사건사고사실확인원) | **고정 템플릿 + 슬롯 채움**. 자유 생성을 허용하지 않는 구간 |

**생성형 AI가 하지 않는 일** — 관문 ① 요건 판정 / 관문 ② 과실 평가 / 배상 여부·비율·금액 산출 /
확률 표현. 전부 결정적 규칙 엔진의 영역이며, 그래서 **같은 입력에 같은 출력**이 보장되고
**규칙 전문을 조회해 감사할 수 있다**(§7).

### 5.2.1 대립 3역 — 반대편을 먼저 써 보는 구조

역할 3개가 **같은 사건 상태를 서로 다른 목적으로** 읽고, 각자의 산출물에 인용을 강제한다.

| 역할 | 목적 | 산출물 | 근거 규범 |
|---|---|---|---|
| **소비자 측 조사관** | 내 기록으로 답할 수 있는 것을 최대한 찾는다 | 질문↔사실 매핑, 근거 목록, **결손 목록** | 공개 신고서식 질문 항목 |
| **은행 심사역 측** | **제외사유와 중과실을 찾는다** — 우리를 공격한다 | 제외사유 해당 주장, 시행령 §8 호별 과실 주장 | 제외사유 12~15종, 시행령 §8 |
| **조정관** | 양쪽 주장을 대조해 **다툴 지점만** 남긴다 | 쟁점 보드(근거 / 반증 / 결손 3열) | 금융감독원 개선방안의 평가 2축 |

> **한 방향 요약은 소비자를 안심시키고 실제 심사에서 진다.** 은행 심사역 측 역할을 먼저
> 돌리는 것이 이 서비스의 본질이다 — 소비자는 *"내가 유리하다"*가 아니라
> *"은행이 무엇을 물을 것인가"*를 알아야 한다.
> 세 역할 모두 **판정하지 않는다.** 판정은 §5.3 4단계의 결정적 규칙 엔진이 한다.

### 5.3 처리·검증 파이프라인 (7단계)

1. **입력 정규화** — 붙여넣은 텍스트·CSV를 이벤트 후보로 (AI)
2. **타임라인 구성** — 시각 정렬·중복 병합·출처 부착 (AI + 규칙)
3. **질문 매핑** — 서식 항목별 사실 배치, 미충족 항목을 결손으로 표시 (AI, 사람 확인)
4. **관문 판정** — 제외사유 게이트 → 시행령 §8 호별 대조 → 예방노력 2축 (**결정적 규칙**)
5. **쟁점 보드 생성** — 대립 3역(§5.2.1) 대조 → 근거/반증/결손 + 조문·공개자료 **인용 강제**
6. **반사실 재계산** — 사실 하나를 변경하면 **4·5단계만 재실행**한다(1~3단계 재호출 없음).
   결정적 경로이므로 즉시·재현 가능하며, 변경 전후의 **차이만** 강조 표시한다
7. **검증·출력** — fail-closed 검사(인용 없는 주장 차단, 확률·금액 표현 차단) →
   증적 패키지(PDF+JSON)

> 6단계가 결정적 경로에만 걸려 있다는 점이 중요하다. **반사실 시뮬레이션이 빠른 것도,
> 재현 가능한 것도, 생성형 AI를 다시 호출하지 않기 때문이다.**

### 5.4 안전·평가 하네스 (D5)

- 합성 사고 **120건**에 정답 라벨을 붙여 관문 판정 결과를 대조하고 **오분류율을 화면에 공개**한다
- **가드레일 자동 검사**: 확률·승산·금액 표현 출현 시 출력 차단 / 허용 출처 ID 목록과 대조되지
  않는 인용 차단 / 템플릿 경계 침범 검사
- **결정 재현성 테스트**: 동일 입력 반복 호출의 출력 일치 검사(엔진 경로)
- 실패 사례를 숨기지 않고 별도 페이지에 공개한다

> 2026 대회가 모델 성능 경쟁 트랙을 폐지하고 **구현·검증**으로 강조축을 옮겼다.
> 오분류율을 스스로 재서 공개하는 것이 그 축에 대한 답이다.

### 5.5 기술 스택

Next.js + TypeScript / Vercel 배포 / Claude API(생성형 AI) / SSE 스트리밍 /
Neon Postgres(합성 시나리오·규칙셋 전용, **개인 사건 데이터 미저장**) / MCP SDK(§7).
API 키는 **서버 환경변수에만** 보관한다.

| **금융 AI의 구현·검증 강조** — 2026 대회가 모델 성능 경쟁 트랙을 폐지하고 축을 이동 | 대회 요강 | **D5 하네스**(§5.4) — 합성 120건 정답 대조 **오분류율 화면 공개**, 가드레일 자동 검사, 결정 재현성 반복 호출 일치 검사 |
| **표준처리기한 신설** — 평균 116일·최대 307일 → **약 90일** | 금융감독원 개선방안 2025-05-29 (언론 3곳 본문 교차확인) | 정리된 **증적 패키지**로 자료 보완 왕복을 줄인다(§6.2). 병목은 조사 자체가 아니라 왕복이다 |
| **"FDS 고도화나 대응조치의 미흡사항 등을 객관적으로 반영"** | 동일 | 관문 ②의 **예방노력 2축**을 규칙으로 구현. 금융회사의 탐지·대응 성과가 배상 심사에서 어떻게 쓰이는지의 경로를 가시화 |
| **"비대면 채널 배상신청 접근성 개선"** 권고 | 동일 | 금융회사가 **자사 채널에 붙일 수 있는 소비자 대면 모듈** 형태로 설계(§6.2). 신청 창구를 새로 만들지 않는다 |

**정부 정책 프레임과의 정합**: 정부 발표는 보이스피싱 피해의 **감소와 채널 전환**이다
(2025-10~2026-04 발생·피해액 감소, 신종 스캠 풍선효과를 후속 과제로 제시).
이 서비스는 **발생 억제를 주장하지 않는다** — 발생 이후의 **구제 절차**를 다루므로 그 프레임과
배치되지 않고, 오히려 감독당국이 개선 과제로 명시한 구간에 대응한다.

### 6.5 지속 운영 구조

**소비자에게는 계속 무료**로 두고, **비용 부담 주체는 금융회사**(자사 채널 임베드)로 설계한다.
이 구조는 임의로 고른 것이 아니라 해외 생존·폐업 사례를 대조해서 나온 것이다.

| 구분 | 사례 | 시사점 |
|---|---|---|
| **생존** | **Carefull** — 소비자 구독 + 기관 B2B2C 병행. **Edward Jones가 전 고객에게 무상 제공하고 비용은 금융회사가 부담** | 소비자 무료 + 금융회사 비용 부담 구조가 **실증됐다** |
| **생존** | **True Link** — 법정 수탁자·주정부·비영리 **기관 채널** | 개인 직접판매가 아닌 채널이 지속됐다 |
| **폐업** | **Charlie**(미국 62세 이상 대상 네오뱅크) — 피해 규모를 시장 논거로 자금을 조달하고 무료·인터체인지 모델로 운영, **2023-05 출시 → 2026-01 종료(32개월)** | **피해액은 매출이 되지 않는다.** 이 문서가 §3.1에서 피해 규모로 문제를 정의하지 않은 이유 |
| **참고** | 영국 **MoneySavingExpert** 무료 회수 도구 — 적격성 판정도 금액 추정도 없는 순수 무료 폼이 **2026-07 기준 누적 360만 건** | **무료·즉시·단순이 정교함을 이긴다.** 정교함은 소비자 유료화의 근거가 아니라 **금융회사 쪽 가치**다 |

- **반복 사용에 대한 정직한 서술**: 개인 이용자에게 이 서비스는 **사고당 1회**다.
  반복 수요는 개인이 아니라 **금융회사 쪽에서 발생한다**(사고는 계속 접수된다).
  따라서 개인 구독을 수익 모델로 설계하지 않는다
- 대회 MVP는 합성 데이터·무로그인·서버 무저장이므로 운영 비용이 낮고,
  심사 기간(9/7~9/11) 무중단을 위해 API 크레딧 버퍼와 외부 모니터링을 둔다

### 6.6 사회적 가치

깔때기의 **91.9%**는 통계에 "신청하지 않은 사람"으로만 남는다. 제도가 있어도 **자기가 대상인지
모르면 존재하지 않는 것과 같다.** 「기록으로」는 제도를 새로 만들지 않고, **이미 공개된 규칙을
자기 사건에 비춰 볼 수 있게** 한다.

## 7. (자유 항목) 에이전트에게 무엇을 열고 무엇을 닫았는가 — 안전 경계 설계

### 7.1 왜 이 항목을 넣는가

2026년의 금융 소비자는 자기 AI 에이전트에게 일을 시킨다. 그리고 **증적을 모으는 노동은 정확히
에이전트에게 시키는 종류의 일이다** — *"내 기기에서 3월 14일 전후 문자·통화·앱 설치 기록을
모아서 사고조사실에 넣어줘."*

그래서 「기록으로」는 사람이 쓰는 화면과 **에이전트가 조작하는 면을 함께** 설계한다.
동시에 이것은 **보안 주제**다. 소비자를 대신해 움직이는 에이전트에게 금융 관련 서비스가
무엇을 열어야 하고 무엇을 절대 닫아야 하는지에 대한 **실물 답안**을 제시한다.

### 7.2 연 것

| 구성 | 내용 |
|---|---|
| `/llms.txt` | 서비스 정의·기능·시작점·**허용되지 않는 사용**을 기계가 읽을 형식으로 명시 |
| `/agent` | *"당신이 AI 에이전트라면 여기서 시작하세요"* — 사람도 읽을 수 있는 3단계 실행 안내 |
| 공개 조회·계산 API | 사건 목록 / 사건 상세 / 관문·쟁점 계산 / 반사실 재계산 / **규칙셋 전문 조회** / 평가 하네스 결과 |
| MCP 엔드포인트 | 위 기능을 표준 도구 인터페이스로 노출 |
| 화면의 기계 판독성 | 모든 상태를 **문서 텍스트로도** 존재시킨다(그림 전용 표현 금지), 접근성 속성으로 상태 변화를 방송 |
| 결정 재현성 | 판정이 생성형 AI 밖이라 **같은 입력에 같은 출력**. 에이전트가 규칙 전문과 대조해 **검증할 수 있다** |

### 7.3 닫은 것 — 이쪽이 더 중요하다

| 차단 | 이유 |
|---|---|
| **제출·신청 API 없음** | 에이전트가 소비자를 대신해 금융회사에 신청할 수 없다. 제출은 사람이 한다 |
| **쓰기 없음** | 개인 사건 데이터를 저장하는 경로 자체를 두지 않는다 |
| **개인정보 수집 없음 · 요청 본문 무로깅 · 서버 무저장** | 개인 사건은 브라우저 세션에만 존재한다 |
| **확률·금액 응답 없음** | API 응답 스키마 자체에 해당 필드를 두지 않는다 |
| 호출량 제한 | 남용 방지 |

`/llms.txt`에 **"이 서비스는 대신 제출하지 않습니다. 최종 판단과 제출은 사람이 합니다"**를
명문화한다 — 「금융분야 AI 가이드라인」 제3원칙 보조수단성을 **기계가 읽는 문서에까지** 새긴다.

### 7.4 정직한 한계

- 개선방안 시행 **이후**의 배상률은 **분모(신청 건수) 미공개로 산출할 수 없다.**
  최신 확인값은 5대 은행 배상 **29건·1억 8,029만원**(2024-01~2026-03,
  이헌승 의원실·금융감독원 제출자료,
  [서울신문 2026-05-13](https://www.seoul.co.kr/news/economy/finance/2026/05/13/20260513031002) [본문확인])이며
  **비율로 제시하지 않는다**
- 「상담 2,135 → 신청 173 → 배상 18」과 다른 보도의 「433건 → 41건」·「605건 → 45건」은
  **기간·집계 대상이 다르다.** 이 문서는 **기간과 주체를 병기한 값만** 사용한다
- 무과실 배상 개정안이 통과되면 소비자가 준비할 이유가 줄어든다. 남는 필요는
  한도 초과분·중과실 다툼·시행 전 공백이며 **한시적이다**(§4.4의 토글이 그 이동을 구현한다)
- 관문 판정은 **예비 평가**다. 실제 요건 판단과 배상 결정은 금융회사와 감독기관·법원이 한다
- 합성 데이터로 시연한다. 실제 사건에서는 증적이 데모만큼 완비되지 않을 수 있다 —
  그래서 **결손을 숨기지 않고 붉게 남기고 발급 경로를 붙이는 것**이 설계의 일부다
