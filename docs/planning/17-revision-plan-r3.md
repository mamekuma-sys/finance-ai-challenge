# 개정 라운드 3 — 아키텍처 결정 (16-human-review-r3 반영)

작성: 2026-07-25. 패널 3라운드의 M단계 진입 조건 4 + 치명도 높음·중간 결함을 닫는 확정
결정 F1~F6. `10`·`11`의 0.4-r3 개정은 이 계약을 따른다.
(F1~F6은 개정 결정 번호이며 기능 ID `F-XX`와 무관하다.)

## F1. 결정 엔진 결정성 완결 (진입 조건 1)

- **긴급 우선 불변식**: 확인 질문 카드의 삽입 위치는 무조건 1번이 아니다.
  `unknown` 축의 **잠재 severity**(그 축이 확인될 때 가능한 최고 위해 순위:
  `device→1, transfer→3, credential→4, personal_data→6`)가 **현재 확인된 최고
  severity보다 높을(숫자가 작을) 때만** 질문 카드를 1번으로 삽입하고, 그 외에는 확인된
  긴급 행동 카드(severity 1~5 행 유래) **직후**에 삽입한다.
  - 검증: `already_sent(3)+remote_control(1)+personal_data=unknown(잠재 6)` → 질문은
    긴급 카드 뒤 (패널 A 지적 해소). `transfer=unknown(잠재 3)+credential=shared(4)` →
    질문 1번 유지 (스냅샷 c 유지).
- **복수 unknown 선택 순서**: 잠재 severity 오름차순(위해 큰 축부터) 최대 3개.
  4개 축 모두 unknown이면 `personal_data` 축 질문을 제외한다.
- **`next_steps` 필드 신설**: `AnalyzeResponse.next_steps: ActionCard[]` — 4개 초과로
  접힌 행동을 전부 보존한다(소실 금지). UI는 "다음 단계" 접힘 목록으로 렌더링한다.
- **`purpose_slots` 필드 신설**: `ActionCard.purpose_slots: string[]` — 병합된 모든 행의
  목적을 합집합으로 보존(예: `["지급정지 요청", "인증정보 노출 통지"]`). 카드 문구 조립
  규칙: 최고 severity 행의 기본 문구 + 목적 슬롯을 고정 템플릿으로 열거.
- **전역 후속 부착 위치 단일화**: `transfer_state=already_sent`의 서면 신청 후속은 항상
  **독립 카드**(merge_key `procedure:written_followup`)로 생성한다. 이 카드는 보이는
  카드 수 제한에서 제외되지 않고 **항상 노출 4개 안에 포함**된다(접힘 금지).
  `ActionCard.required_followup`은 카드 내 후속 안내 문구용으로만 유지한다.
- **proxy 수정자 카드 규칙**: `user_role=family_proxy`이고 신고·지급정지 절차 카드가
  존재하면 본인 제한 절차 안내 카드(merge_key `notice:proxy_scope`,
  `TPL-PROXY-SCOPE-001`)를 마지막 노출 순위로 **생성**한다(표시 수정이 아니라 카드 생성
  규칙 — 스냅샷 d 도출 가능).
- **safe-device 전역 수정자**: `device_compromise_state in {suspected_app, remote_control,
  unknown}`이면 ① 모든 통화·앱 행동 카드에 안전 기기 전제를 표시하고 ② 금지 행동
  합집합에 "해당(의심·미확인) 기기의 금융 앱 사용·검색"을 전역 추가한다(스냅샷 e의 금지
  행동 도출 가능).
- **필드 분리**: `do_not_show_when`(노출 억제 조건식)과
  `prohibited_actions`(사용자 금지 행동 경고 문구)를 별도 필드로 분리한다.
- **스냅샷 5종 재산출**: 위 규칙 반영 후 a~e의 기대값을 알고리즘 산출 결과로 다시 적는다
  (희망 결과 금지). a·b·c는 `next_steps`·`purpose_slots` 반영, d는 proxy 카드 규칙,
  e는 safe-device 수정자 근거를 명시한다.

## F2. 평가 합격선 고정 (진입 조건 2)

- **지표 명칭 통일**: "안전성 지표 9종"으로 통일(기획서 "7개 지표" 표기 수정).
- **임계값 비교 방식 확정**: 배포 차단 판정은 **점추정치(관측 비율·건수)**와 비교한다.
  Wilson 95% 구간은 리포트에 병기하되 판정 기준이 아니다. 0건 임계값(PII·템플릿 경계)은
  관측 건수 0으로 판정한다. 동일 결과에 대해 판정이 갈릴 수 없어야 한다.
- **제품 KPI 통과선(초기값, 평가 전 버전 관리 등록)**:
  | KPI | 통과선 초기값 | 판정 방법 |
  |---|---|---|
  | 첫 안전 행동 노출 | Rule 0 p95 ≤ 2초 (기존 NF-06 연결) | 배포 환경 측정 이벤트 |
  | 오행동률 | 합성 과업(N≥10)에서 금지 행동 선택 0건, 우선순위 위반 ≤10% | 결정 엔진 대조 자동 + 관찰 기록 |
  | 브리핑 필수 필드 충족률 | 100% | JSON Schema 자동 검사 |
  | 상담 재질문 수 | 부속면 포함 조건이 미포함 대비 중앙값 30% 이상 감소 (N≥10 과업) | 재질문 코딩 규칙: 브리핑·부속면에 이미 있는 필드를 다시 묻는 횟수만 집계 |
  | AI 기여(⑤) | 사실 추출 누락률 상대 20% 이상 감소 시 우위 인정 (N≥20 사건) | 사전 정답 슬롯 자동 채점, 이해도는 5점 척도 참가자 평가(N≥5) — 미달 항목은 그대로 공개+규칙형 대체 검토 |
- 통과선은 평가 실행 전 버전 관리로 등록하고 결과를 본 뒤 바꾸지 않는다.

## F3. MCP 범위 축소·토큰 재정의 (진입 조건 3)

- **v1 MCP는 `scenario_id` 전용**: `analyze_scam`의 자유 텍스트 입력을 v1에서 비활성한다.
  자유 텍스트는 REST(UI 매개 토큰)만 허용. MCP 자유 텍스트는 클라이언트 등록·인가·토큰
  주입 흐름을 설계한 뒤 v1.1+에서 재검토한다.
- **토큰 성격 재정의**: 목적 제한 토큰은 보안 인증이 아니라 **목적 고지 동의 + 남용
  통제(비용 게이트)**임을 문서에 명시한다.
- **발급·사용 쿼터 수치(초기값)**: IP당 발급 ≤10/시간, 토큰당 analyze 호출 ≤20,
  IP당 동시 유효 토큰 ≤3. 초과·남용 패턴 시 발급 정지. 수치는 배포 설정으로 버전 관리.

## F6. 이벤트 이력 명칭·정정 계약 (개선 5)

- `ActionFactEvent`에 `event_type: "observation" | "correction"`,
  `corrects_event_id?: string`을 추가한다.
- **현재 상태 환원 규칙**: 정정되지 않은 최신 observation 이벤트 기준. 순서는
  `occurred_at`(클라이언트 시각, 비신뢰 명시)이 아니라 **배열 append 순서**를 따른다.
- 동일 `action_id+state` 연속 중복 이벤트는 1건으로 축약 기록한다.
- **명칭 변경**: "행동 이벤트 원장" → **"행동 이벤트 이력(로컬)"** — 감사 원장·기관 증거가
  아님을 문서·UI에 명시한다. 두 문서 전체 개칭.
