## 0. 이번 검토가 바꾼 것 — 4가지

원안(B-1 사고조사실)은 근거가 가장 단단했지만 **자기반증 하나가 안 풀린 채 남아 있었다**:
*"증적은 사고 전에 쌓여야 하는데, 사고 전에는 아무도 이 서비스를 켜지 않는다."*
이번 검토는 그 반증을 포함해 4개를 고친다.

| # | 바뀐 것 | 왜 |
|:-:|---|---|
| **1** | 축을 **「사전 증거보전」 → 「사후 증적 복원」**으로 이동 | 사전 설치가 필요 없어지고 **자기반증이 소멸**한다 (§2) |
| **2** | 문제 정의를 **「두 개의 관문」**으로 재서술 | 34.7% + 62% — **가장 아픈 곳**이 과실 판정이 아니라 그 **앞의 배제**였다 (§1) |
| **3** | **A-면(에이전트 면) 신설** — 3면 구조 | 심사가 사람+AI다. 그리고 이게 **성장 경로 자체**다 (§4) |
| **4** | D2를 **반사실 시뮬레이터**로 확보 | 「타임라인 재생」은 D2로 약하다. 규칙 위 what-if는 진짜 D2다 (§6) |

**컨셉은 바꾸지 않는다.** 재현 부서(전자금융사고 조사 + 책임분담 심사 6단계)도, 4개 층 조사에서
남은 유일한 좌표(증적 확보·재구성 + 무료 셀프서비스)도 그대로다. 날을 세운 것이다.

## 1. 문제 재정의 — 규모가 아니라 **두 개의 관문**

### 한 문장

> **한국의 배상 심사는 두 번 거른다. 신청의 34.7%는 「피해자가 직접 이체했다」는 이유로
> 심사에 들어가지도 못하고, 들어간 것 중 62%는 「당신 과실」로 끝난다.
> 두 관문의 규칙은 전부 공개돼 있는데, 그 규칙에 넣을 사실만 소비자 쪽에 없다.**

이 문장이 원안보다 강한 이유 3가지:
1. **피해액으로 시작하지 않는다** — 루브릭 R2 감점 트리거(−2) 회피. Charlie($30.5M, 32개월 폐업)가
   증명한 실패 서사를 반복하지 않는다
2. **두 관문이 곧 엔진 2단계다** — 문제 서술이 그대로 아키텍처가 된다 (문제↔솔루션 정합)
3. **34.7%가 더 아프다** — 62%는 "졌다"이고 34.7%는 **"싸울 기회조차 없다"**이다.
   그리고 이건 소비자가 **신청하기 전에는 절대 모른다**

### 근거표 (전부 본문확인 인용)

| 사실 | 값 | 기간·주체 | 출처 |
|---|---|---|---|
| **관문 ①** 심사 제외 — 사유: 피해자 직접 이체·로맨스스캠·중고사기 | **60건 / 34.7%** | 2025 국감 | `19-verify-final3.md` L146 |
| **관문 ②** 심사 완료분 중 "이용자 과실" 거절 | **68/109건 = 62%** | 은행권 ~2025-04 | 이데일리 2025-07-24 |
| 배상 실적 | **29건 / 1억 8,029만원** | 5대 은행 2024.1~2026.3 | 서울신문 2026-05-13(이헌승 의원실) |
| 같은 기간 피해액 (대조용, 첫 문장 금지) | 1,856억원 | 동일 | 동일 |
| 처리기간 | 평균 **116일**, 최대 **307일** → 개선안 표준 **약 90일**(2025-09 시행) | 은행권 | 이투데이 2025-05-29 |
| 소비자 요구 1순위 = **사후 보상 31.5%**, 이상거래 감지는 4위 8.6% | — | 2024 한국은행, n=3,551 **대면**, ±1.69%p | 브리프 §5 |
| 은행 민원 전체 −10.2%인데 **보이스피싱 관련만 +125.7%**(+2,423건, 은행 민원의 20.1%) | — | 2025 금감원 | 브리프 §5 |
| 【대조】영국 PSR 의무배상 — 손실액의 **89%** 배상, 주의의무 미달 거절 **2~3%** | £243m / 352,000건 | 2024-10~2025-12 PSR | PSR 대시보드 |

> **62%와 89%를 나란히 놓는 것이 문제 정의의 핵심 장면이다.** 영국은 입증책임을 전적으로
> 지급기관에 지우고(PSR SR1 §1.6), 소비자 주의의무 미달 거절이 2~3%다. 한국은 심사에 올라간
> 사건의 62%가 "당신 과실"로 끝나고, 그 과실 판정의 재료를 소비자가 **기억으로 제출**한다.

### 왜 지금인가

- 개선안(2025-09 시행)이 **처리기한은 줄였지만 배제사유는 그대로 뒀다** → 관문 ①은 미해결
- 무과실 배상 법안(2215538·2215547) **정무위 1소위 계류** → 통과하면 다툼이 **"은행이 중과실을
  입증할 수 있는가"**로 이동한다. 그 다툼의 재료도 똑같이 **소비자 기기 안에** 있다
- ⚠️ 통과한 2216766은 **가상자산 건이며 무과실·5,000만원 조항 미포함** — "통과"로 쓰면 즉시 오류

### 타깃 페르소나 (한 문장)

**"보이스피싱을 당했는데, 마지막 이체 버튼을 내 손으로 눌렀다"는 사람.** — 관문 ①에서
가장 많이 걸리는 유형이고, 은행 창구·콜센터에 가장 많이 도착하는 민원이고,
**어디에서도 "당신은 이 제도 대상이 아니다, 대신 이 경로가 있다"는 말을 못 듣는 사람**이다.

## 2. 자기반증의 해소 — 축을 「사전 보전」에서 「사후 복원」으로

원안의 방어선은 *"사고 이전의 증거보전"*이었다. 그건 죽는다 — 사고를 예상하고 앱을 까는 사람은 없다.

**증적은 이미 기기에 다 있다.** 하나은행 신고서 p.3이 묻는 것과 기기가 가진 것을 맞춰 보면:

| 신고서 p.3이 **기억으로** 묻는 것 | 기기에 **이미 있는** 것 |
|---|---|
| 스미싱 링크 클릭 여부 | 문자함 원문 + 수신 시각 |
| 악성앱 설치 여부 | 설치 앱 목록 + 설치 시각 + 패키지명 |
| 제3자에게 제공한 정보 6종 | 통화 기록 + 문자 송신 이력 |
| 인터넷·폰·오픈뱅킹 사용 경험 및 빈도 | 은행 앱 알림 이력 + 거래내역 |
| 평상시 휴대전화 잠금 방식 | 기기 설정 |

> **공백은 "증거가 없다"가 아니라 "심사 질문의 형식으로 번역할 사람이 없다"이다.**

축이 이렇게 바뀌면:
- **사전 설치 불필요** → 자기반증 소멸
- **오늘 당장 쓸 수 있다** (사용자 요구 직결) — 사고 당한 사람이 지금 폰에 있는 것으로 시작한다
- 4개 층 조사에서 확인된 공백(증적 확보·재구성 + 무료 셀프)은 **그대로 유지**된다
- Refundee(£140m, 성공보수 15~25%)와의 경계도 유지 — 그쪽은 **거절 이후**, 우리는 **신청 이전**

**남은 반증 3개와 대응은 §9.**

## 3. 솔루션 — 「기록으로」, 3면 구조

> 은행이 **기억으로 답하라고 요구하는 항목**을 **기록으로 답하게** 하고,
> 그 기록으로 **두 관문을 미리 통과시켜 보는** 시스템.
> 승산을 점치지 않고, 대신 제출하지 않는다. **은행이 물을 것에 대한 답을 미리 갖춘다.**

### 서비스명

**「기록으로」** — 부제 *"내 편의 사고조사실"*

이름이 방어선을 겸한다: 아무 결과도 약속하지 않고 **방법만** 말한다.
(대안: 「사고기록실」 / 「증적」 / 「관문」 — 「기록으로」가 핵심 문장을 그대로 브랜드로 쓴다는 점에서 우위)

### 산출물은 화면이 아니라 **사건 파일**

소비자가 얻어 가는 것을 고정한다 — **다운로드 가능한 「증적 패키지」**:
1. 사건 타임라인 (초 단위, 출처 표기)
2. 신고서 p.3 질문 ↔ 내 기록 **대응표**
3. 쟁점별 근거 자료 목록 + **결손 목록 + 발급 경로**
4. 적용 조문·보도자료 **인용 전문**
5. **PDF + JSON 동시 출력** (JSON은 §4 A-면과 같은 스키마)

**제출은 하지 않는다.** 조립해서 넘기고, 소비자가 은행 앱·창구로 직접 낸다
(변호사법 §109·§34 / 행정사법 §3① 방어선).

### 6단계 = 재현하는 실제 부서

| 단계 | 부서 업무 | 「기록으로」가 하는 것 |
|:-:|---|---|
| 1 | 요건 심사 (제외사유 15/12종) | **관문 ① 시뮬레이션** — 걸리면 즉시 **대체 경로** 제시 |
| 2 | 행동 사실조사 (소비자 진술) | **기억↔기록 전환** — 기기 기록을 질문 카드에 매핑 |
| 3 | 금융거래 사실조사 (은행 자체 수집) | 같은 항목을 **소비자 쪽에서도** 세운다 (비대칭 해소) |
| 4 | 이용자 과실 평가 (시행령 §8 4개 호) | **관문 ② 쟁점 보드** — 호별 근거/반증/결손 |
| 5 | 금융회사 예방노력 평가 | 은행이 무슨 경고를 언제 했는지도 **증적 대상** (PSR §1.10 정합) |
| 6 | 비율 결정 → 통보 → 이의 | **증적 패키지 출력** + 기한 시계 |

### 「기록으로」가 하지 않는 것 (설계 원칙 = 규제 방어선)

| 금지 | 근거 |
|---|---|
| 확률·승산·예상 배상률 출력 | DoNotPay FTC $193,000 (2025-02 최종명령) |
| "AI가 판정한다·결정한다" 서술 | 「금융분야 AI 가이드라인」 2026-06-22 제3원칙 보조수단성 |
| 대화창(챗봇) | 카카오뱅크 대화형 AI 검색 누적 500만 명 — 점유됨 |
| 체크리스트 문서 생성 | 하나은행 8쪽 양식이 이미 그것 (T4) |
| "국내 최초·유일" | Refundee·APP Claims·Clearwise 존재 |
| 대신 제출·대리 | 변호사법·행정사법 |

## 4. A-면 — **에이전트가 조작 가능한 금융 소비자 서비스** (신설)

### 왜 이게 승부처인가

심사는 **사람 + AI 두 층**이고, 심사위원이 자기 에이전트에게 *"이 URL 써보고 알려줘"*라고
시킬 가능성이 높다. 그런데 대부분의 팀 데모는 **에이전트에게 보이지 않는다** —
캔버스 애니메이션, 클릭해야 나오는 상태, SPA 셸. 에이전트는 빈 화면을 보고 돌아간다.

> **시각적 화려함과 기계 판독성은 기본값이 서로 충돌한다. 둘 다 설계한 팀만 두 층을 다 통과한다.**

그리고 이건 심사용 장치가 아니다. **제품의 성장 경로 그 자체다** —
소비자가 증적을 모으는 노동은 정확히 2026년에 사람들이 **자기 에이전트에게 시키는** 종류의 일이다.
*"내 폰에서 3월 14일 전후 문자·통화·앱 설치 기록 모아서 사고조사실에 넣어줘."*

### A-면 구성 6종

| # | 구성 | 내용 |
|:-:|---|---|
| 1 | **`/llms.txt`** | 서비스 정의·할 수 있는 것·시작점·API 목록·**하면 안 되는 것** |
| 2 | **`/agent` 페이지** | *"당신이 AI 에이전트라면 여기서 시작하세요"* — 3단계 복사·실행 가능 지시. **사람이 읽어도 되는 문서** |
| 3 | **공개 JSON API (무인증·읽기/계산 전용)** | `GET /api/scenarios` · `GET /api/scenario/{id}` · `POST /api/investigate` · `POST /api/counterfactual` · `GET /api/rules` · `GET /api/eval` |
| 4 | **`/mcp` (Streamable HTTP)** | 같은 기능을 MCP 도구로: `list_scenarios` `investigate_case` `simulate_counterfactual` `get_rule` `explain_gate` |
| 5 | **UI의 기계 판독성** | 모든 상태를 **DOM 텍스트로도** 존재시킨다(캔버스 전용 금지) · `data-testid` 고정 · ARIA live region으로 상태 변화 방송 |
| 6 | **결정 재현성 보증** | 엔진이 LLM **밖**이라 같은 입력 → 같은 출력. 에이전트가 **검증할 수 있다** |

### A-면의 안전 설계 — 이게 금보원 축의 가점 요인

에이전트에게 API를 여는 것은 그 자체로 보안 주제다. **무엇을 열고 무엇을 닫았는지를 실물로 보여준다:**

- **열림**: 규칙 조회, 사건 계산, 반사실 시뮬레이션, 평가 하네스 결과
- **닫힘**: **제출 API 없음** (에이전트가 대신 신청할 수 없다) · 쓰기 없음 · 개인정보 수집 없음 ·
  요청 본문 무로깅 · 서버 무저장 · rate limit
- `llms.txt`에 **"이 서비스는 대신 제출하지 않습니다. 최종 결정과 제출은 사람이 합니다"**를 명문화
  → 「금융분야 AI 가이드라인」 보조수단성을 **기계가 읽는 문서에까지** 새긴다

> 2026 대회가 모델경쟁 트랙을 폐지하고 **구현·검증**으로 축을 옮겼다.
> "에이전트에게 무엇을 열 것인가"의 실물 답안은 정확히 그 축이다.

## 5. 30초 데모 재설계 — **쌍둥이 사건**

원안 데모(단일 사건 + 3토글)를 **두 사건 비교**로 바꾼다. 34.7%가 가장 아픈 지점이기 때문이다.

**0~6초** — 화면에 사건 두 개가 나란히. 겉보기 조건이 같다.
> **사건 A**: 원격제어앱 설치 → 제3자가 **4,800만원 무단이체**
> **사건 B**: 검사 사칭 전화 → **내가 직접 4,800만원 이체**

**6~14초** — 두 타임라인이 **동시에 초 단위 재생**된다. 이벤트가 쌓이고, 오른쪽엔
하나은행 신고서 p.3의 **실제 질문 7장**이 회색 카드로 떠 있다.

**14~20초** — **「관문 ①」이 내려온다.**
- A는 통과. 카드가 초록으로 열린다.
- **B는 여기서 멈춘다** — *「피해자가 직접 지급지시한 거래」 제외*. 화면이 붉게 닫히고,
  **"신청 60건 중 34.7%가 여기서 멈춥니다"** 가 뜬다.
- **그리고 B에게 다른 문이 열린다** — 통신사기피해환급법 환급 / 금감원 분쟁조정 / 민사.
  **각 경로의 기한 시계가 함께 돈다.**

*→ 이 6초가 이 데모의 심장이다. 은행 소속 심사위원이 "저게 제일 많이 오는 민원"이라고 알아본다.*

**20~26초** — A로 넘어가 **「기억으로 답하기 ↔ 기록으로 답하기」** 토글.
회색 물음표 7장에 타임라인 이벤트가 **날아가 꽂히고**, 카운터가 **0 → 11**,
**채워지지 않은 2장이 붉게 남는다 = 지금 확보해야 할 증거 + 발급 경로.**

**26~30초** — **반사실 슬라이더** 한 번. *"링크를 클릭하지 않았다면"* 을 켜면
시행령 §8 제2호 쟁점이 통째로 재배열되고, **어떤 사실 하나가 심사를 가르는지**가 눈에 보인다.
(끝에 **「무과실 개정안 적용」** 토글 — 물음이 *"제외 대상인가"*에서 *"은행이 중과실을 입증할 수 있는가"*로 뒤집힌다)

> 30초 안에 **상태가 네 번 갈라진다**: 관문① 통과↔차단 / 기억↔기록 / 사실 하나의 반사실 / 현행↔개정안.
> **확률도 금액도 출력하지 않는다.** 그리고 **모든 상태가 DOM 텍스트로도 존재해 에이전트가 같은 것을 읽는다.**

## 8. 오늘 당장 쓸 수 있는가 / 성장 경로 / 누가 돈을 내는가

### 오늘 당장

**쓸 수 있다.** 사고를 당한 사람이 **지금 폰에 있는 것**으로 시작한다 —
문자 원문 붙여넣기, 거래내역 CSV, 설치 앱 목록, 통화 기록. 무로그인·무설치.
개인 사건 데이터는 **브라우저 세션에만 존재하고 서버에 저장하지 않는다**(요청 본문 무로깅).
데모용 합성 시나리오 120건은 **별도로** 제공해 심사위원이 즉시 체험할 수 있게 한다.

### 성장 경로 — 규칙셋 교체만으로 확장된다

엔진은 도메인 무관이다(`RULES`·상태 필드·출처가 전부 데이터). **부서 하나가 다루는 사고 유형이
늘어나는 구조**이지, 다른 사업으로 뛰는 게 아니다.

| 단계 | 규칙셋 | 근거 규범 |
|:-:|---|---|
| v1 (9/6) | 전자금융사고 책임분담 심사 | 전금법 §9·시행령 §8, 제외사유 15/12종 |
| v2 | 카드 부정사용 | 여신전문금융업법 §16 |
| v3 | 전산장애 보상 | 서울중앙지법 2022가단5281302 산정식 |
| v4 | 보험 사고조사(고지의무·사기 의심) | 상법 §651, 보험업법 |

공통 형태: **"회사가 공개된 규범으로 내 과실을 판정하는데, 그 판정의 재료를 내가 기억으로 제출하는" 모든 절차.**

### 지불 주체 (S1)

- **은행** — 2025-09부터 **표준처리기한 약 90일**을 맞춰야 한다. 병목은 **자료 보완 왕복**이다.
  정리된 증적 패키지가 들어오면 사실조사 구간이 줄고, 금감원이 요구한 "담당자당 처리 건수 감축"과
  직결된다. 게다가 금감원이 **"비대면 채널로 쉽게 신청하도록 시스템 개선을 권고"**했다 —
  은행이 붙일 것을 찾고 있는 시점이다
- **실증 구조**: Carefull → Edward Jones (기관이 비용 부담, 소비자 무료) / True Link(기관 채널)
- **소비자는 계속 무료** — MoneySavingExpert의 교훈: 판정도 추정도 없는 무료 폼이 **360만 건**을 흡수했다.
  정교함은 유료화의 근거가 아니라 **은행 쪽 가치**다

## 9. 남은 반증과 대응 (숨기지 않고 기획서에 쓴다)

| 반증 | 대응 | 잔여 위험 |
|---|---|---|
| **무과실 법안 통과 시 전제가 무력화** | 같은 엔진이 두 법제를 다 돈다. 개정 후엔 **"은행이 중과실을 입증하는지 검증하는"** 도구로 이동(토글로 이미 구현). 한도 5,000만원 초과분·중과실 다툼·시행 전 공백은 남는다 | 중 — 6~12개월 시계, 제출·심사 기간엔 미도래 |
| **모수가 작다** (신청 173건 / 배상 29건) | 그 작음 자체가 문제 근거다. 그리고 **모수는 신청 건수가 아니라 관문 ①에서 돌아선 사람 + 아예 신청을 포기한 사람**이다 — 보이스피싱 민원 **+125.7%**(은행 민원의 20.1%)가 그 층의 크기 | 중 — "그래서 몇 명이 씁니까" 대비 답변 필요 |
| **무료 단순 폼이 정교함을 이긴다** | 첫 화면을 **단순하게** 유지한다: 사건 하나 클릭 → 관문이 내려온다. 정교함은 그 뒤에 둔다 | 저 |
| **Refundee형 인간 대행이 더 낫다** | 경계가 다르다 — 그쪽은 **거절 이후**, 우리는 **신청 이전**. 그리고 유료(15~25%)·한국 미진출 | 저 |
| **10%는 개선 전 값** | 최신 실측(2026-05-13) **29건·1억 8,029만원**으로 교체 완료. 개선 후 배상률은 **분모 미공개로 산출 불가** — 그렇게 표기한다 | 저 |
