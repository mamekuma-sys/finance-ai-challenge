# 스코핑 리뷰 — 대회 기간 대비 솔루션 복잡도 재평가

작성: 2026-07-24. 목적: 후보 21개가 "6주 안에 되는 것"에 맞춰 하향 스코핑되지 않았는지 검증하고,
대회 기간 전체에 맞는 적정 야심도(ambition)를 재설정한다.

## 1. 대회 기간 구조 재정의

원 리서치는 "6주 1인 MVP 가능성"만 물었다. 실제 대회는 3단계다:

| 단계 | 기간 | 할 일 | 함의 |
|---|---|---|---|
| **v1.0 심사본** | 7/24 → 9/6 (6.4주, 주 20h+ = 개인 ~130h + AI 에이전트 레버리지) | 기획서·기능명세서·배포 URL 제출 | 여기서 이미 "완성된 서비스"로 보여야 함. 최소 데모가 아니라 심사 통과 기준 |
| **URL 동결** | 9/7 11:00 ~ 9/11 | 수정 금지, 무중단 유지 | 안정성 리스크 버퍼를 v1.0 스코프에 포함해야 함 |
| **v2.0 본선용** | 9/12 → 10/8 (약 4주) | 최종 코드 ZIP + 발표자료, 10/13 발표 | 본선 진출 시 **추가 4주의 고도화 기간이 존재** — v1에서 아키텍처를 확장 가능하게 깔아야 함 |

**결론**: "6주짜리 솔루션"이 아니라 **"6주에 v1.0을 완성하고 4주 더 고도화할 수 있는 10주짜리 아키텍처"**로 스코핑해야 한다. 1인이지만 Claude(오케스트레이터)+Codex(sol/xhigh) 병렬 위임 체제라 실효 개발력은 1인 이상이다.

## 2. "너무 간단함"의 판정 기준

심사위원 관점에서 다음 중 하나라도 해당하면 탈락 위험:

- **T1. 프롬프트 래퍼**: 핵심이 "LLM 1회 호출 + 예쁜 UI" — GPT 위에 프롬프트만 얹은 것으로 보임
- **T2. 정적 지식 챗봇**: RAG + FAQ 응답이 전부 — 은행들이 이미 다 하는 것
- **T3. 계산기+설명**: 규칙 계산에 LLM 설명을 붙인 것 — 스프레드시트로 대체 가능해 보임
- **T4. 체크리스트 생성기**: 출력이 결국 정적 문서

반대로 "적정 깊이" 신호 (v1.0에 최소 3개 이상 포함 목표):

- **D1. 멀티에이전트 오케스트레이션**: 역할이 분리된 에이전트들이 협업 (분석→계획→검증)
- **D2. 실시간·동적 데이터 처리**: 스트림/시뮬레이션 엔진, 상태가 살아있는 시스템
- **D3. 비정형 데이터 파이프라인**: 문서·이미지·대화의 구조화 (파싱→추출→그래프화)
- **D4. 도메인 계산 엔진**: LLM 밖에서 도는 진짜 로직 (위험 스코어링, 시뮬레이션, 그래프 분석)
- **D5. 평가·안전 장치**: 오답률 측정 하네스, 가드레일, 근거 인용 강제 — 금융 AI의 차별화 포인트
- **D6. 양면(다중 사용자) 시스템**: 소비자용 + 운영자/기관용 뷰 동시 제공

## 4. 방향 A~D 재스코핑 (10주 아키텍처 기준)

### A. 사기 대응 골든타임 코파일럿 — 업그레이드 스코프

단순 버전(RAG 챗봇+행동 카드)이 아니라 **5개 레이어 풀스택**으로:

1. **시뮬레이션 엔진** (D2): 합성 거래·문자·통화 스트림을 실시간 생성 — 심사위원이 "피해 진행 중" 시나리오를 라이브로 체험
2. **멀티에이전트 분석** (D1·D3): 수법 분류 에이전트 + 위험 스코어링 + 계좌·번호·URL 관계 그래프 구축
3. **골든타임 오케스트레이터** (D4): 시간 감쇠 모델(지급정지 골든타임 30분) 기반 행동 우선순위 + 신고서·증거보존 문서 자동 생성
4. **양면 뷰** (D6): 피해자(쉬운말·다국어·고령자 모드) + 은행 담당자(경보 브리핑) 화면
5. **안전 하네스** (D5): 합성 시나리오 100건 오분류율 대시보드 — "AI 보안 비서를 검증까지 했다"는 메시지
- v2.0(본선): 음성 통화 실시간 분석, 연합 시나리오(다기관 전파) 추가

### B. 외국인 완주 에이전트 — 보강 조건

번역·체크리스트가 아니라: 오류 코드→원인 진단 엔진(D4) + 서류 이미지 검증(D3) + 은행 업무 상태머신 + 상담원 인계 요약(D6). 이 4개가 없으면 T2로 전락.

### C. 소상공인 내비게이터 — 보강 조건

공고 파싱 파이프라인(D3, 비정형→구조화) + 적합성 매칭 엔진(D4) + 현금흐름 몬테카를로 시뮬레이션(D4) + 서류 사전심사 에이전트(D1). "검색 서비스"로 보이는 순간 죽는다.

### D. 설명 가능한 금융 판단 — 보강 조건

KB-1/생보협-1·3은 원래 깊이가 있음. 약관·공시 파싱의 정밀도(D3)와 인용 검증 하네스(D5)가 승부처.

## 5. 결론

- 원 리서치의 "6주 실현 가능성 높음" 축은 **하향 편향**을 만들었다. 이 문서의 D1~D6 기준으로 재스코핑한다.
- 방향 선택과 무관하게, 최종 문제 정의에는 "v1.0(9/6)까지 D-신호 3개 이상 + v2.0(10/8) 확장 로드맵"을 명세한다.
- ❌ 4개 후보는 단독 채택 불가. 단, 다른 방향의 접근성 레이어(부품)로는 재사용 가능.
